# 文档转 PPT 生成器

用公司模板（`迈胜PPT模板.pptx`）生成 PPT：把文档内容按内置的 19 套版式渲染成正文页，
封面填 deck 标题 + 日期、目录页填真正的目录、封底保持模板原样，并带一套可回归的 QA。
版式库里还能加**自定义版式** —— 上传一张 PPT 版式截图，AI 识别成可复用的版式。

> 方案与决策记录见 [`docs/方案-文档转PPT生成器.md`](docs/方案-文档转PPT生成器.md)
> zcode skill 解读见 [`docs/pptx-skill-分析.md`](docs/pptx-skill-分析.md)

> ⚠️ **回退模式 ≠ 可用产出。** 未配置模型、或模型调用失败时，大纲与规划走确定性回退：
> 能跑完、版式合法、结构自检通过，但**内容的取舍与标题的主张**做不了 ——
> 它只能把原文的条目原样搬进版式，所以正文常超出框高（几何检查会报
> `text_overflow`，配了模型时由修复回环压短）。
> 版式的**选择**现在兜底也能做（同样是意图 → 候选 → 容量过滤，实测 13 页正文
> 用出 6 种版式、无相邻重复），但「这一页该讲什么」仍然只有模型能定。
> **要拿到可用的东西，必须配模型。**
>
> ⚠️ 时间线（`timeline_vertical`）改成左右交替后，每条只占半幅、说明**只有一行** ——
> 兜底路径 `_split_item` 切出来的说明常有 26–106 字，超出部分会被 `_fit()` 截成 `…`
> （截断记进 `TRUNCATIONS` 并进日志，是可听见的，不是静默的）。要完整说明，
> 得配模型让它压到 22 字内，或改投 `phase_grouped_flow`。
>
> 回退产物**不再是静默的**：大纲 JSON 里带 `_meta.generated_by`，`.md` 预览、
> Web 界面和生成日志三处都会明确标出「这是兜底产物」。以前它只 print 一行
> stdout，界面上和模型产出长得一模一样 —— 结果就是拿着一份兜底大纲当模型产出看。

## 配置

```bash
cp .env.example .env     # 然后填 key
python run.py config     # 看当前配置状态
```

`.env.example` 里有各家服务商（智谱 / DeepSeek / 通义 / OpenAI / Azure / 本地 vLLM）的填法。
两组配置：

- `PPTGEN_LLM_*` —— 文本模型，用于**生成大纲**与**规划每页版式**
- `PPTGEN_VISION_*` —— 视觉模型，用于**AI 看图验收**（需支持 base64 图片输入）

视觉留空且 `PPTGEN_VISION_FALLBACK_TO_LLM=1` 时会回退复用文本模型配置。
**两者都没配也能跑完整条链路**，只是质量退化。

几个与版式直接相关的开关：

| 变量 | 默认 | 作用 |
|---|---|---|
| `PPTGEN_MIN_PAGES` / `PPTGEN_MAX_PAGES` | 13 / 18 | 正文页数区间。**章节分隔页不占这个额度**（见上文 ④） |
| `PPTGEN_SECTION_DIVIDERS` | `1` | 是否在正文里插入章节分隔页；设 `0` 关掉 |
| `PPTGEN_OUTLINE_SEGMENT` | `1` | 骨架分不出章 / 分得太碎时，是否让模型把页单元归成几章（见上文 ①″）；设 `0` 关掉，退回纯确定性 |
| `PPTGEN_CONTENT_MODE` | `balance` | `strict` 只做结构整理 / `balance` 允许合并提炼 / `enrich` 可补写过渡。Web 端这一项是**每次现选**的（「内容策略」下拉，初值就是 `.env` 里这个值） |
| `PPTGEN_OUTLINE_MAX_TOKENS` / `PPTGEN_PLAN_MAX_TOKENS` | 取 `max(PPTGEN_MAX_TOKENS, 16000)` | 两个阶段的输出上限。**推理模型会把额度烧在 reasoning 上**，给小了正文直接为空、静默退回兜底（实测 `deepseek-flash` 给 8000 就烧掉 8000） |

## 跑起来（Web 前端 · 推荐）

```bat
cd C:\gyb-software\programs\program-pptcreator02
.venv\Scripts\python.exe server.py
```
然后浏览器打开 **http://127.0.0.1:8000**

页面是「左侧栏 + 主区」：左侧常驻**状态栏**与**制作进度**（按 `info / active /
warning / success` 上色，长任务时有点在跳），主区从上到下是选源 → 大纲确认 →
生成日志 → 生成结果。

1. **选源** —— 两种方式，用单选切换：
   - **上传文件**：把 `.docx / .pdf / .txt / .pptx / .md` 拖进落区，或点「选择文件」。
     可一次拖多个，但**同时只有一枚胶囊生效**（链路一次解析一份文档），
     点胶囊切换「使用中」，✕ 从磁盘删掉。
   - **选择已有文档**：从项目根目录里挑（`Dify 介绍与实战.pptx`、`迈胜PPT模板.pptx` 等）
2. **审阅并修改大纲** —— 章节名、页标题**直接在页面上改**（这是人工确认的落点），
   也能展开「高级」直接编辑 JSON，两边双向同步
3. **生成进度** —— 实时日志（规划分批进度、几何检查结果都会打出来）
4. **预览与下载** —— 逐页渲染图（点开可放大、`←/→` 翻页）+ 几何检查徽章 + 下载 pptx
5. **按页修改** —— 预览图下面就是那个统一窗口：一个输入框里说清**哪几页**要怎么改
   （可以写多条），顶部开关选「小范围修改」还是「整页重做」。先生成方案、
   逐条看过 diff（标量新值还能直接手改）再应用 —— 见下面的「按页修改」一节。
   每张预览图左上角是勾选框（用于「引用选中的页」）、右上角是版式名。

换端口：`server.py --port 8080`。只用标准库，无额外依赖。

### 上传接口

前端走的是 `POST /api/upload?name=<文件名>`，**裸 body 就是文件字节**
（不是 multipart —— 服务端要保住「零依赖」，自己解析 boundary 不划算）：

```bat
curl -X POST --data-binary "@需求说明.docx" "http://127.0.0.1:8000/api/upload?name=需求说明.docx"
curl "http://127.0.0.1:8000/api/sources"                      :: 列出根目录 + 已上传
curl -X DELETE "http://127.0.0.1:8000/api/uploads/需求说明.docx"
```

单文件上限 40MB，扩展名限制在 `SOURCE_EXT` 内，重名自动加 `-1`。
上传的文件落在 `out/uploads/`（已 gitignore），重启后仍会出现在文件胶囊里。

> ⚠️ 若上传报「读出来是 DLP 密文」，说明**读文件的那个进程**不是加密客户端
> 信任的进程（实测 git-bash 的 curl 读 `.txt` 就是密文，chrome 一般不是）。
> 见下方「工程约束 §6」。

**一条命令走完（推荐）**

```bat
%PY% run.py full --src "Dify 介绍与实战.pptx"          :: 做到大纲就停下等你确认
%PY% run.py full --src "Dify 介绍与实战.pptx" --yes    :: 跳过确认一路走完
```

`--yes` 会依次执行：解析 → 大纲 → 规划 → **修复回环** → 渲染 → QA，成品落在

## 文件日志

每跑一次流程，在 `out/logs/` 下留一个**自包含**的文件夹：

```
out/logs/2026-09-21-11-02-Dify 介绍与实战/
├── run.json                  本次流程的关键值（每个阶段结束增量落盘）
├── run.log                   完整流水（CLI 的 stdout / Web 的任务日志）
├── Dify_介绍与实战-2.pptx      生成的成品
├── Dify_介绍与实战.pptx        源文件 —— **仅当源是上传的才放**
└── Dify_介绍与实战.outline-2.json  人工确认后的大纲
```

- **命名**：`<年-月-日-时-分>-<任务名>`，同分钟重名自动加 `-2`。
  CLI 的任务名取 `--name`，没有就用源文件 stem；Web 取源 stem。
- **源文件只有上传的才归档**：用根目录文件时源本来就在仓库里，没必要再存一份。
- **同名不覆盖**：源文件和成品常常同名（都叫 `<stem>.pptx`），后进的那个加 `-2`。
  到底哪个是哪个，看 `run.json` 里的 `source.archived_as` / `artifacts.pptx.archived_as`。
- **写入是原子的**（临时文件 + `os.replace`）：进程崩在写的中途也不会留下
  截断的、解析不了的 run.json —— 而那恰恰是最需要它可读的时刻。
- **写日志失败不会拖垮流程**：磁盘满、目录被删，都只往 stderr 吼一句就继续。

`run.json` 记四组：

| 组 | 内容 |
|---|---|
| 运行基本信息 | 起止时间、耗时、入口（cli/web）、命令、是否成功、错误 |
| 源文档与结构 | 文件名、来源（upload/root）、原始文件名、字数、块数；骨架方法与章节树 |
| 各阶段质量与降级 | 每个阶段的耗时与成败；大纲是 `llm` 还是 `fallback`、模型名、warnings；规划的版式分布；QA 的 error/warn |
| 配置快照 | 页数区间、内容策略、模板名 + **模板 sha256**、各阶段 token 预算 |

> 为什么值得有：在这个板块之前，**跑一次流程事后几乎无法追溯** ——
> Web 的日志在内存里（重启就没），CLI 只有 stdout，落盘的只有产物。
> 结果是「这份大纲质量很差」摆在那里，却看不出它其实是兜底产物、模型压根没跑。

**关掉**：`PPTGEN_LOG=0`。**换目录**：`PPTGEN_LOG_DIR`。
**不复制成品**（省 8MB/次）：`PPTGEN_LOG_PPTX=none`。

> `out/` 整个被 gitignore，所以日志不进版本控制。

## 大纲是怎么生成的

借鉴了 [book-to-skill](https://github.com/virgiliojr94/book-to-skill) 的思路：
**先用确定性代码抽出文档结构，再让模型在既定结构上做内容取舍**（"Structure, not a summary"）。
分三层：

**① 结构抽取（`structure.py`，纯确定性、不调模型）**
从解析出的 blocks 里抽章节树。章节信号按可靠性从高到低尝试，认不出来就往下一级退化：

| 方法 | 判据 |
|---|---|
| `outline` | 文档自带的目录：PDF 的 `/Outlines` 书签树，取最浅一层当章节 |
| `divider` | pptx 的分隔页：某一页最大字号 ≥ 全 deck 标题字号中位数 × 2.2，且是短序号 |
| `kicker` | 正文页左上角的章节标签（`01 初识 DIFY`）。**与分隔页取并集** —— 实测源文档第 5 章只有 kicker 没有分隔页 |
| `depth` | 标题层级（pdf 升出来的标题、docx 的 Heading 1、md 的 `##`） |
| `numeric` | 显式数字标题（`第3章` / `Chapter 5` / `01 产品介绍`） |
| `flat` | 都不成立 → 单章 |

`depth` 排在 `numeric` **之前**：层级是解析层给的**事实**，数字前缀是猜的 ——
实测制度文件里的 `1. 定义：` 这类列表项会被数字前缀当成章标题，凭空多出两章。

同时识别封面 / 目录页 / 封底为 front matter 并整体排除（目录页的内容是各章标题
粘在一起的产物，留着会让模型把目录条目当成章节）。第 1 章的区间会**向前扩到第一个
非前置块** —— 封面之后、第一个章节标记之前往往就是真内容（《Dify》那份是 3 页产品介绍），
掉在章节之外的块谁也拿不到（`_content_index` 是按页名取内容的）。

实测 `Dify 介绍与实战.pptx` → 5 章 18 页；`Dify 介绍与实战.pdf` → 5 章（书签）；
`IS-0001 AI应用安全管理制度.pdf` → 4 章（`第一章`…`第四章`），都与源文档一一对应。

**①′ PDF 的标题从哪来（`parse._parse_pdf`）**
早先这里把**每页第一行**当标题 —— 而那份 PDF 每页第一行是**页码**，40 页抽出 41 个
`1`/`2` 这样的「标题」、`doc['title']` 成了 `"1"`，真正的章标题全躺在正文里当段落，
骨架于是只剩 1 章（「大纲全部落在一个章节下」就是这么来的）。现在按开源实现收敛出来的
顺序取信号：**书签 → 编号模式 → 字号**，并先做两件清理：

- **页眉页脚**：同一行重复出现在 ≥3 页，且「≥50% 的页」或「落在页首前两行且 ≤40 字」
  → 整份丢弃（前者抓每页都盖的水印，后者抓 `Dify: Product Introduction` 这种只在
  开头几页、却占着页首的页眉）。
- **页码**：纯数字且落在页首/页尾。

标题判据是**相对**的：行高 ≥ 正文行高（按字符数加权的众数）× 1.30 算标题，≥1.60 才算
第 1 层；编号模式（`第X章`/`第X条`/`1.2.3`/短 `1. `）另外给一层，两者取更浅的。
每页都要有一个**页单元**（没标题就用该页第一行兜底，层级记 2 —— 它不声称层级）；
字号量不出来（扫描件、伪造字体）就不猜，只靠编号与书签。

> 这套顺序与判据不是自己拍的，是对着开源实现核对来的：
> - **`书签 > 编号 > 字号`**：docling 的 `HeadingHierarchyModel` 把这条顺序直接写进了
>   代码（[PR #3688](https://github.com/docling-project/docling/pull/3688)）。它同时点明了
>   为什么非要自己推层级 —— **版面模型只标「这是不是标题」，没有任何一个会给出层级**。
> - **正文基线 = 覆盖字符数最多的那个字号**（不是行数最多的、更不是均值），
>   同 pymupdf4llm 的 `IdentifyHeaders`。
> - **中文编号阶梯**（`第X章` → `第X条` → `一、` → `（一）` → `1.` → `1.1`）抄的是
>   RAGFlow `deepdoc/parser/pdf_parser.py::proj_match()` 与 LightRAG 的
>   `STYLE_KEY_PRIORITY`；`部分` 要排在 `部` 前面，`（一）`/`一）` 两种括号都认，
>   大数字诱饵（`2026年度`）靠「数字后必须跟分隔符」挡掉。
> - **书签匹配要宽容**：书签里带编号、正文那行不带（或反过来）都常见，两种写法
>   都比一遍 —— docling 用 `SequenceMatcher` 比值 0.92，这里用「去掉编号后相等」。
>
> 没做的一件是**解析打印出来的目录页**：开源里几乎没人做好（marker 把它当表格、
> 抽不出条目；PyMuPDF / pymupdf4llm 明确不认）。这里只把目录页认出来当前置信息排除。

**①″ 分章兜底（`pipeline._segment_chapters`，会调一次模型）**
确定性信号抽不出结构（纯正文的 txt），或者抽得太碎（30 个同级标题各算一章）时，
把**已有的页单元**清单交给模型归成 3–6 章。它只做**分组**，所以能严格校验：
区间必须从 1 起、首尾相接、覆盖到最后一个页单元 —— 不合格整份丢弃。章名与块区间
都由代码给，锚点体系不受影响。

触发条件是两个相反方向的病：`章数 < 2 且页单元 ≥ 4`（结构信号缺失）、
`章数 > min(7, 页数上限 ÷ 2)`（太碎；再往下走 `_compress_sections` 会把排不上的
章**整章丢掉**）。模型不可用时：太碎 → 按页单元均分（至少不让内容被丢）；
只有 1 章 → **保持原状**（怎么分是语义判断，没模型就别硬凑章数）。
章节数决定分隔页预算，所以它跑在 `_divider_budget()` **之前**。
关掉它：`.env` 里设 `PPTGEN_OUTLINE_SEGMENT=0`。

**② 内容生成（`pipeline.py`）**
把骨架摘要 + 正文交给模型。正文短于 24k 字就一次调用；更长则**按章分片**，
每章一次、各自只带该章的正文 —— 这样 prompt 有界，长文档也不会因为截断丢章。
每页除标题外还产出 `hint`（展示形态）、`intent`（表达意图，**枚举**，决定这一页
能挑哪些版式）、`source`（来源标注）、`anchor`（内容取自哪一条源页标题）。

**③ 校验与修正**
模型给的页数区间、章节数这些约束只是**建议**，代码这边才是执行：
页数落区间、章节数等于骨架章数、标题非退化（复用「≥4 个实义字符」的判据）、
每页 hint/source 非空、`intent` 在枚举内。不合格就带着违规清单重试一次；
仍不合格则确定性修正（补章节、补字段、按标题/形态补 `intent`、超页数就**保章压页**），
并把修了什么记进 `_meta.warnings`。**不会因为模型不听话就整份退回兜底** —— 兜底产出更差。

**④ 章节分隔页（规则插入）**
每章开头插一页「大号章节号 + 章节名 + 一句导语」的隔断页，让「换章了」在翻页时可见
（在此之前 5 个章节只靠左上角那行 kicker 区分）。它是**结构页，不交给模型挑** ——
结构页没有内容可依据，让模型在版式库里选只会选错（借鉴 PPTAgent 的做法：
功能性版式按位置规则插入，不参与内容驱动的选择）。

它要占页数预算，所以 `_divider_budget()` 只在「扣掉之后每章还留得下一页正文」时才插
（判据 `hi >= 章数 × 2`）；装不下就**完全不插**，而不是砍正文。关掉它：
`.env` 里设 `PPTGEN_SECTION_DIVIDERS=0`。分隔页不计入 `page_count`（正文页数），
但记在 `divider_count` / `total_pages` 里。

## 版式系统

### 内置 19 套版式与单一真相来源

版式的**元数据与渲染函数写在一起**（`layouts.py` 里的 `@layout(...)` 装饰器），
登记进 `layout_spec.REGISTRY`。喂给模型的版式目录、压文案时的字数预算、
版式选择用的容量约束，全部从这一份注册表生成 —— 在这之前它们是**三份手写清单**，
已经漂移：同一个 `stats.label`，目录里写「≤20 字」、预算里写「≤22 字」，
模型先看到 20、被压时被告知 22。

| 类别 | 版式 |
|---|---|
| 结构骨架 | `section_divider` |
| 陈述 | `statement` |
| 指标 | `stat_hero`（单焦点）、`kpi_grid`（3–6 个等权指标） |
| 概念 | `definition` |
| 并列 | `numbered_columns`、`tinted_bands`、`quadrant` |
| 对照 | `comparison_rows` |
| 复合 | `split_main_aside`（主区编号要点 + 辅区小表/数字/要点） |
| 流程 | `process_chain`、`phase_grouped_flow`、`timeline_vertical` |
| 层级 | `layered_stack` |
| 数据 | `data_table`、`metric_trend`（原生图表） |
| 状态 | `progress_checklist` |
| 结论 | `executive_summary` |
| 引语 | `quote` |

新增的 8 套是按**实测缺口**挑的，不是凑数（其中 `node_flow` 后来又被删除，见下）：

- `split_main_aside` —— 实测约三成的大纲 hint 是「主 + 辅」两件事
  （「五步流程图 + 六参数对照表」）。原先 12 套**全是单一构图**，这类内容必然丢一半。
- `phase_grouped_flow` —— 起因是 `node_flow` 的节点框只有 2.30" 宽、13pt 单行约 12 字。
  实测那 8 个节点里 **6 个被 `_fit()` 静默截断**成「小红书正文 · 爆款写作…」，
  而几何报告是全绿的。分组流程单框 3.09"、可折两行（约 34 字）放得下。
- `section_divider` / `kpi_grid`（4–6 个指标原先无处可放）/ `metric_trend`
  （趋势与占比原先表达不了）/ `progress_checklist`（状态语义原先没有）/
  `executive_summary`（结论先行）/ `layered_stack`（层 × 模块的二维结构）。

**`node_flow` 已删除（内置 20 套 → 19 套）。** 它被 `phase_grouped_flow` 取代：后者正是
为「节点多、标签长」而加的，两者在 `process` 意图上是同一个位置。删除时顺带关掉了
一条**真实可达的静默截断路径** —— `_heuristic_slide` 里 `pick()` 的回落是
`[c for c in order if c in allowed] or allowed`，而 process + 6–8 条时
`allowed[0]` 就是 `node_flow`，于是「源条目 >13 字就排除 node_flow」那道守卫**被绕过**，
40–120 字的源句真会被砍成 13 字残句渲染出来。

### 自定义版式：从截图添加

内置的 19 套是**代码**（`layouts.py` 里的渲染函数）。版式库里还能有**自定义版式** ——
上传一张 PPT 版式截图，视觉模型识别出版面结构，程序渲一版试片给你看，你只需要决定
**采用**还是**放弃**。入口是网页的「版式管理」页（`/layouts`），或命令行：

```bash
%PY% run.py layouts                                  # 列出版式（来源 / 状态 / 分类 / 容量）
%PY% run.py layouts --add-image shot.png --adopt     # 从截图识别并入库
%PY% run.py layouts --disable quadrant               # 禁用（内置也可以）
%PY% run.py layouts --rm my_layout                   # 删除（只对自定义版式开放）
%PY% run.py layouts --check                          # 自定义版式的样例过一遍自检
```

**自定义版式是数据，不是代码。** 一份 `layouts_custom/<名字>.json` 描述「版面上有几个
区块、每个区块放什么内容」，由 `layout_dsl.render_blocks` 渲染。九种区块：`text`、
`bullets`、`columns`、`kpi`、`table`、`steps`、`rows`、`rule`、`band`。

三条设计决定（理由见 `layout_dsl.py` 的模块注释）：

- **只渲纯文本，不支持段内混排** —— 逐 run 折行与纯文本量宽对不上，对不上就是溢出。
  强调靠区块自身的 `color`。
- **字号由程序的 `fit` 阶梯决定，不由模型决定** —— 模型只给框，写多了降字号，
  再不行才截断（记进 `TRUNCATIONS`，可听见）。
- **高度一律自适应**（`rh = min(上限, 可用高度 / 条数)`），从 `comparison_rows`
  固定行高越出画布那次教训抄来的。

**入库前的闸门**（用户不能对话修正，所以必须自动跑完）：归一化 + 校验 →
渲试片过几何检查（零 error、无 `text_overflow`/`text_overlap`、**无截断**）→
把「原图 + 试片」发给视觉模型判**版面分区**是否复现 → 任一步不过就带违例清单重试
（默认 2 轮）→ 仍不过就**不入库**，界面显示原因。

构图比对只拦**结构性**差异（栏数、区块位置与相对大小）。装饰性差异必然存在 ——
试片是声明式画的，页面里嵌的截图那块是空的、序号没有底色块；这些记进备注、不阻断，
否则「左文右图」这类页面永远入不了库。识别提示词也写明：嵌在页面里的截图**不要
建区块**（图区内容属于内容，不是版式）。

**禁用不等于删除。** `layouts_custom/_state.json` 对内置与自定义一视同仁：被禁用的
版式不进候选、不进喂给模型的目录，但渲染函数还在 —— 旧 deck 照样能渲染、能按页改。
**删除只对自定义版式开放**（内置的定义是代码，删不掉也不该删）。

> ⚠️ 识别要用**看得见图**的模型（`PPTGEN_VISION_*`）。没配时这个入口用不了，
> 但版式的查看 / 启停 / 删除照常。

> 版式预览图落在 `out/visual/_layouts/`（gitignore）。**新克隆下来是空的** ——
> 页面上点一次「生成缺失的预览图」就会渲好并缓存（19 页，每页十几秒）。

### 版式选择：意图 → 候选 → 终选

模型**不再从全部版式里盲选**。实测盲选的错配率很高：大纲写「六参数对比表 +
三类调优技巧」，规划却选了 `timeline_vertical`；写「左侧五要点 + 右侧版本对照表」，
选了 `numbered_columns`（表直接丢了）。现在是三段式：

1. **意图分类** —— 大纲阶段给每页标一个 `intent`（`layout_spec.INTENTS`，11 个枚举值：
   statement / definition / enumeration / comparison / process / timeline /
   hierarchy / quantitative / status / summary / quote）。
2. **候选收缩 + 容量预筛**（纯程序）—— 按意图取候选，再用**内容形态**过滤：
   条目数是否落在版式的 `[min_items, max_items]`、有没有表格、有没有数字。
   候选按贴合度排序（以该意图为主职的版式排在前面），取前 4 个。
3. **候选内终选** —— 模型只在候选里挑，并且要按该版式的容量声明填字段。
   挑了候选外的版式、或条目超容量，**这一页改用确定性生成**（字段必然对得上）——
   只把 layout 名改掉会缺键、渲染时才炸。

> ⚠️ **容量预筛只看「源文条目数」，不看「源文条目有多长」。**
> 源条目天然是一整句（实测 40–120 字），而版式的单条预算是针对**成品**的（22 字）——
> 模型的工作正是把长句压短。早先拿源条目长度去卡候选，版式被筛得只剩 `statement`，
> 13 页内容全塌成一种版式。单条字数改为**事后**校验成品
> （`pipeline.overflow_reason`），而且只覆盖真正会被静默截断的单行定高字段。

### 反单调

- **相邻页不得用同一版式**（硬约束，在 LLM 路径与兜底路径上共用）。
  它同时消灭「连续两页一样」和「连续三页一样」——实测旧产出里第 12、13 页
  就是相邻的两个 `node_flow`（该版式已删除，约束本身不受影响）。
- 候选集里优先挑没用过的；候选用光时从「条目可裁剪」的版式里借一个
  （裁掉两条，好过连着三页同一种构图）。
- `reuse_friendly=False` 的版式（`quote` / `executive_summary`）全篇只该出现一次。

### 静默截断不再静默

`_fit()` 遇到超长会加省略号 —— 它让文字不再溢出，于是**几何检查全绿**，
问题只在肉眼看渲染图时才暴露。所以每次截断都记进 `tokens.TRUNCATIONS`，
由 `build(on_log=...)` 取走并写进流程日志（`take_truncations()` 取走即清空 ——
Web 端是长驻进程，不取走会跨 job 累积）。回归测试里有两条断言：
成品里不该出现省略号、截断必须能被 `on_log` 收到。

> 标题**不再靠截断兜底**了：分隔页与封面的标题会折行（见下节）。

### 标题长度：预算是版面事实

三处标题各自能放多少字，是量出来的，不是文风偏好：

| 位置 | 框 | 字号阶梯 | 容量 |
|---|---|---|---|
| 封面 | 6.18"×2.16" | 54pt 起，最多两行 | ≈20 字 |
| 分隔页 | 7.73"×1.60" | 40pt 起，最多两行 | 一行≈14 字 |
| 正文页眉 | 11.33"×0.62" | 26pt 单行 | ≈24 字（两行会压到正文） |

三道防线，从源头到兜底：

1. **prompt 里写死预算**，并点明骨架里 `—` 之后是副题、不是章节名的一部分。
2. **超长标题交给模型缩写**（`pipeline._shorten_titles`）：一次调用、同序返回，
   压短但保留数字与专有名词、保留章节号前缀。**失败就保留原文**，绝不因为
   「缩写没成功」退回兜底；没有超长项时一次调用都不发。
3. **渲染层折行**（`tokens.fit_block`）：字号阶梯从大到小试，两行内放得下就用
   最大的字号（14 字在 40pt 下差 0.44" 放不进一行 → 40pt 折两行，而不是把字号
   压到 26pt 挤一行）。折行是硬换行（估算偏乐观就会在 PowerPoint 里再折一次），
   所以宽度估算留了 5% 余量，断点优先落在标点/空格后、不劈拉丁单词、行首不挂
   避头标点。**阶梯的下限低到实际到不了**，截断只在用户把标题改成极端长度时发生。

> 骨架文本（`structure.skeleton_digest`）把章名与副题**分两行**写也是同一件事：
> 早先拼成 `## 01 初识 Dify　—　什么是 Dify · 设计初衷 · 九大核心理念`，
> 模型就照抄整行当章节名（30+ 字），分隔页必然被截成 `01 初识 Dify　—　什么是 Di…`。
> 分开写是釜底抽薪 —— 没有整行可以抄。

### 封面 / 目录 / 封底

模板自带的这三页以前是**生硬套用**：封面一个字都不填（`spec['title']` 从 pipeline
一路传到 `build()` 却没人消费），目录页的标题被手写成 28pt `DARK` 压在同色的深灰
通栏上（等于看不见），条目被压到 16pt。

现在的原则是**只写文字、不动格式**（`build._fill` 只设字号与 `a:ea`）：

- 封面：标题走同一套 `fit_block`（按**量出来的**可用宽高，扣掉占位符内边距），
  副标题写日期（`spec['subtitle']` 可覆盖）。标题为空时**完全不动封面**。
- 目录：标题写「目录」，条目就是 `toc`。字号/颜色/对齐/项目符号全部继承 layout，
  于是自动回到模板的「深灰通栏 40pt 白字 + 品牌红圆点 24pt 列表」。
- 封底：原样保留（品牌收尾页）。
- 目录**空了也要填**，否则成品上会留着模板的「议题一/议题二/议题三」。
- ⚠️ 这三页在 `geometry.analyse` 的默认 `skip={1,2,n}` 里 —— **不在几何自检范围内**，
  排版得自己算准，`fill_agenda` 因此额外按模板的 24pt 估算一遍高度并告警。

## 按页修改

生成之后，结果区的预览图下面有一个**统一窗口**：在一个输入框里用自然语言说清
**哪几页要怎么改**（一个框里可以写多条），顶部一个开关决定**整框**按哪种模式走。

| 模式 | 做什么 | 护栏 |
|---|---|---|
| **小范围修改** | 只改字段值（标题压短、某条文案改写、给某句加强调），**版式不变** | 路径白名单 + `expect` 现值比对 + 预演构建 |
| **整页重做** | 这一页重讲，**可以换版式**、重挑内容。封面/目录例外：它们没有版式可换，重做 = **重出文案**、仍写在模板那一页上 | 候选版式 + 相邻页不重复 + 容量 + 预演构建 |

流程是**两阶段**：`生成修改方案` 只提案、一个字节都不写盘；面板上把每条改了什么
（`title`：「旧」→「新」）逐条列出来，标量的新值**还能直接手改**，确认后才
`应用选中的修改`。这是刻意的 —— 自然语言改稿最容易崩的地方就是「它到底动了哪几个字」。

### 页码：用户看到的序号 = 预览图序号

```
预览第 N 张 = pptx 第 N 页 = slides[N-3]（0 基）= 几何报告里的 issue['slide']
```

| 预览页 | 是什么 | 微调 | 整页重做 |
|---|---|---|---|
| 1 / 2 | 封面 / 目录（模板页） | 改 `title`/`subtitle`、目录条目 | ✓ 重出文案，仍用模板那一页（不换版式） |
| 3 … n-1 | 正文页或**章节分隔页** | 字段值 | 正文页可换版式；分隔页只能微调章节名/导语 |
| n | 封底 | ✗（没有可改内容） | ✗（没有可改内容） |

封面与目录**没有版式可换**（它们就是模板的第 1、2 页，`build.fill_cover` /
`fill_agenda` 往占位符里写字），所以整页重做在它们身上退化成**重出这一页的文字**：
模型看着整份大纲重拟封面的标题/副标题、重写目录条目。走的是**和微调同一条落盘路径**
（`revise.commit_rewrite` → `commit_page`），所以两条模式产生的补丁、大纲同步、
面板上的逐条 diff 全都不用另写一套。两条约束写死在这里：**目录条数不能变**
（一条对应一个章节，增删会让目录与分隔页对不上，直接拒），**封面标题 20 字**
（超了 `fill_cover` 会折行再缩字号，全试完还装不下就静默截断 —— 所以超了只是
提醒，但一定会说出来）。这两页**不在几何检查范围内**（`qa/geometry.py` 默认跳过
第 1/2/n 页），宽度只能靠 `pipeline._toc_line` 夹取，夹了会在方案里写明哪一条被裁。

**这份映射只在 `revise.build_page_index()` 里实现一次**，前端只显示不算，
喂给模型的页码表也是它生成的 —— 不让模型自己数页码。
（`slides[]` 里混着章节分隔页，实测某 15 页 deck 里 5 页是分隔页，
所以「正文第 5 页」和「预览第 5 张」能差出好几页。）

### 补丁为什么是「带现值的 ops」而不是整页重写

模型返回逐路径的操作，每条都要回带 `expect`（该路径**当前的值**）：

```json
{"path": "items[2].desc", "expect": "成本下降三成", "value": "成本下降 30%", "why": "…"}
```

- **「版式不变」成为结构上不可能** —— 路径表是从这一页的实际数据推导的，里面没有 `layout`
- **`expect` 拦住模式 A 最危险的失败**：模型把 `items[2]` 按 1 基理解、指着第 2 条 ——
  补丁完全合法、会静默落盘、改错了条目。只有比对现值能拦住
- 路径只开放到「元素」这一层：`phases[i].nodes[3]`、`lines[0][1]` 一律拒绝
  （半个 run 会破坏富文本）

三档校验，从便宜到贵：路径/类型/条目数 → `expect` 比对 → **预演构建**
（`build` + 几何检查，约 1–2 秒）。第三档才是真正的容量门：`overflow_reason`
实测只覆盖 3/19 套内置版式的单条字数（`data_table`、`statement`、`metric_trend` 等
在 `_ITEM_FIELDS` 里根本没有规则）。被拒的条目**不影响其余**，并给出人能看懂的原因
（「这一页没有标题位 —— 它的大字就是正文本身」）。

模式 B 走 `pipeline._plan_batch`，**不复用 `repair.repair_slide`** —— 后者的三道护栏
全部指向「压缩」：`layout` 不许改、`_text_len` 必须变短，而换版式和变长正是重做的核心。
它按内容形态**放行全部意图**（`layout_spec.candidates_any_intent`）：用户说
「换成能对比的形式」时，锁在原大纲意图的候选里模型根本选不到 `comparison_rows`。

### 改动的真相来源

| 改什么 | 落哪 | 会不会被覆盖 |
|---|---|---|
| 正文页内容字段 | `<deck>.deck.revised.json` | 安全 |
| 正文页 `title`/`kicker`/`source` | 同上 | 安全（`_normalise_plan` 只在字段为空时回填） |
| **目录条目 / 封面标题 / 封面副标题** | **必须同时写 `<name>.outline.json`** | 会被重算（`pipeline.py:1557`/`:1563` 无条件从大纲重算 toc、封面标题派生自 `outline['title']`、副标题取自 `outline['subtitle']`） |

最后一行三种字段**微调与重做走的是同一条路**：都由 `commit_page` 写 deck、
报出 `cover.title` / `cover.subtitle` / `toc` 三条大纲补丁，再经
`apply_outline_patch` 落到 `<name>.outline.json`。

最后一行还有**前端的一半**：`/api/generate` 的输入是**页面上的 `state.outline`**，
不是磁盘那份。所以 apply 之后前端会把 `outline_patch` 合并回去并重渲大纲编辑器 ——
只写盘的话，用户不刷新页面直接点「生成 PPT」还是会被覆盖。
另外 `/api/generate` 启动时会检查修订台账，有记录就先打一条
「之前有 N 处人工修改，本次重新规划会覆盖掉」。

### 只重渲改动的页

渲染一页要 **8–10 秒**（每页一次 officecli 进程），而 `build()` 每次都是全量重建 pptx。
所以按页记指纹：`out/visual/<deck>/.pages.json` 里存**每一页的像素由什么决定**
（封面 = 标题 + 生效后的副标题、目录 = toc、正文 = `slides[i]`、封底 = 常数），
digest 变了才重渲。实测改一页 **26 秒**（含两次模型调用），而不是整份重渲的 220 秒。

三个容易写错的细节，都写在代码注释里：`page` 键要剔出指纹（`build` 会原地写它）、
封面副标题要哈希 `today_cn()` 的**生效值**、**渲失败的那页绝不能记成「最新」**
（记了就再也不会重渲，用户会一直看着旧图而日志正常）。

改前那一帧会另存成 `page-NN-<rid>.png`（同一个目录，`/preview/` 零改动就能取到），
弹层里可以切换「改动前 / 改动后」。前端给重渲过的图带 `?v=` —— URL 不变而图变了，
不带就是浏览器给旧图。

### 命令行

```bat
%PY% run.py revise --deck out\plans\x.deck.repaired.json --text "第5页标题压到10字内；第8页那说明改短"
%PY% run.py revise --deck out\plans\x.deck.repaired.json --mode rewrite --text "第13页重讲，换成能对比的形式"
%PY% run.py revise --deck out\plans\x.deck.repaired.json --mode rewrite --text "封面换个标题；目录条目每条压到 20 字"
::  加 --apply 才真的落盘（会先跑预演构建，撑破版面就不写）
```

`--apply` 之前只打印方案、一个字节都不写。**修订需要文本模型**：没配时直接失败，
不学 outline/plan 的「总能跑完」兜底 —— 出不了补丁的「成功」是最坏的静默失败。

| 变量 | 默认 | 作用 |
|---|---|---|
| `PPTGEN_REVISE_MAX_PAGES` | 3 | 一次提交最多重做几页。`llm` 没有取消接口，单次调用最坏 9 分钟，一页一次 —— 不设上限的话「这五页都重做」要等 45 分钟且停不下来。**被截断的条目会明确告诉你没做**，不静默少做 |

接口：`POST /api/revise`（提案）、`POST /api/revise/apply`（应用）、
`GET /api/revision/<rid>`（取回草稿 —— 刷新页面后还能接上）、`GET /api/deck/<name>`。

### 已知边界

- **不能改页数**（拆页/删页）：页码映射、按页指纹、`build` 的模板页删除逻辑都建立在页数稳定上
- **封面/目录的整页重做不换版式**（它们就是模板的第 1、2 页），也不能增删目录条目
  （一条对应一个章节）。这两页**不在几何检查范围内**：宽度靠 `_toc_line` 夹取、
  夹了会在方案里写明哪一条被裁；高度只能靠 `fill_agenda` 的估算与构建日志里的截断提醒
- **封面副标题不能清空**：空串会被 `template_new` 当作「这条没给」，`check_ops`
  也不收空值。想去掉副标题目前得改大纲 JSON
- **图表数据不支持微调**（`metric_trend`）：改图表请用「整页重做」
- **老 deck 会被整份拒绝**：实测 4 份历史产物里躺着已删除的 `node_flow`，
  `render_slide` 遇到未知版式直接 `KeyError`，而 `_normalise_plan` 会把它**悄悄换成
  `statement`** —— 那会静默改掉用户正在看的那一页，所以宁可拒绝并让他重新生成

## 必须遵守的工程约束（都踩过）

### 1. 只用 `Blank` / `Title Only`

`Full Blank` 上有个 `Rectangle 3`（`x=9.19, y=0, 4.15×1.24`）会盖住母版的 MEVION 徽标，
渲染出来是**纯白页**，没有任何公司品牌元素。
`Blank` / `Title Only` 同样没有内容占位符可以自由画，但**保留了红顶栏 + 徽标 + 装饰弧线**。

### 2. 所有 `add_slide` 必须在删页之前完成

python-pptx 按「现有 slide 部件数量」推算新文件名。先删再增会让新页与既有页
**partname 撞名**（zip 内出现两个 `slide4.xml`、两个 rId 指向同一部件），
PowerPoint 报修复或显示错页，而**模板封底被静默覆盖丢失**。`build.selfcheck()` 会拦住它。

### 3. `Inches()` 不要套在 `Pt()` 上

早期版本对四个尺寸统一套 `Inches()`，调用方传的却是 `Pt(0.75)`（已是 EMU），
于是 `Inches(9525)` 得到 **9525 英寸高**的巨型矩形，所有发丝线变成覆盖整页的色块。
**officecli 查不出这个**（它只检查右边界），只有自写边界扫描能抓。
现在 `tokens.hrule/vrule` 内部做 `pt/72` 转换，只接受英寸。

### 4. 内容右边界 12.00"

装饰弧线的图片框位于 `x=10.19~15.13`（伸出画布外），实测墨迹自 `x≈12.00` 起。

### 5. 每个 run 显式设字体

模板主题的 `fontScheme` 里 `ea` 为空，不显式设 `<a:ea>` 中文会走系统默认。

### 6. 有些文件在磁盘上是密文

本机装了透明加密客户端，部分文件带 `%TSD-Header-###%` 文件头。
**非信任进程**（Read/grep/od/PowerShell/officecli/git-bash）打开这类文件拿到的是密文
（乱码或 "File contains corrupted data"），`cmd.exe` 拿到的是明文。
officecli 属前者 —— 所以它读不了加密的 pptx，排查时别当成文件损坏。

抢救办法（重定向必须交给 bash，不能写进 cmd 里）：

```bash
cmd //c "type src\pptgen\qa\geometry.py" > /tmp/recover.py
cp /tmp/recover.py src/pptgen/qa/geometry.py
```

详见 `docs/pptx-skill-分析.md`。

### 7. 别用 python 写源文件

同上一节的透明加密：**`python.exe` 写出来的文件会被加密**，随后 Read / grep 全变密文。
改代码用 Edit/Write 工具（它们写的文件保持可读）。
已经在 python 里跑的批量改写，写完立刻 `Read` 一下确认没变成 `%TSD-Header-###%`。

> 注意 python **读**明文文件是正常的（`import` 照样成功），只有**写**会触发 ——
> 所以「脚本跑完没报错」不能说明文件是好的。

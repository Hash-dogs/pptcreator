# 程序运行逻辑

**实现文档**：程序从输入文件到成品 pptx 走完哪些链路、每一步内部怎么决策、失败时退到哪。

环境准备、`.env` 各项配置、启动命令、日志与产物落在哪见 [`程序运行文档.md`](程序运行文档.md)。

---

## 一、总览

链路固定为七段：

```
解析 → 大纲 → 人工确认 → 规划 → 修复 → 渲染 → 检查
```

按页修改发生在成品之后，改的是同一份规划产物，只重渲受影响的页。

两个入口共用这条链路：

| 入口 | 文件 | 说明 |
|---|---|---|
| 命令行 | `run.py` | 分步执行，或一条命令走完 |
| 网页 | `server.py` | 零依赖本地服务，带图形界面 |

大纲与规划两段优先调用模型，没配模型或模型调用失败时走确定性兜底。兜底能跑完整条链路，版式合法、结构自检通过，但内容的取舍与标题的主张做不了，只能把原文条目原样搬进版式。兜底产物在大纲 JSON 的 `_meta.generated_by` 里标成 `fallback`，预览、前端与日志三处都会显示。

代码分工：

| 模块 | 职责 |
|---|---|
| `parse.py` | 传入文件解析 |
| `structure.py` | 文档结构抽取，不调模型 |
| `pipeline.py` | 大纲生成、逐页规划 |
| `layout_spec.py` | 版式元数据注册表，唯一真相来源 |
| `layouts.py` | 内置 19 套版式的渲染函数 |
| `layout_dsl.py` | 声明式版式：区块渲染器 + 归一化 + 校验（自定义版式走这条） |
| `layout_store.py` | 自定义版式的存储、注册、启用禁用（`layouts_custom/`） |
| `recognize.py` | 截图 → 版式声明：识别、试片闸门、构图比对 |
| `tokens.py` | 设计令牌与绘图原语 |
| `build.py` | 组装 pptx，套模板 |
| `repair.py` | 文案压短的修复回环 |
| `revise.py` | 按页修改 |
| `qa/geometry.py` | 几何检查 |
| `qa/visual.py` | 渲染成图与 AI 看图 |
| `runlog.py` | 流程日志落盘 |

## 二、解析

### 2.1 支持的格式

| 扩展名 | 解析库 | 说明 |
|---|---|---|
| `.pptx` | python-pptx | 两遍扫描 |
| `.docx` | python-docx | 按 Heading 样式取层级 |
| `.pdf` | pypdfium2 | 书签优先，其次编号，再次字号 |
| `.txt` / `.md` / `.markdown` | 内置 | 标题与列表按符号识别 |

两个入口：`parse(path)` 走磁盘路径，`parse_bytes(data, name)` 走内存字节流。网页上传优先走内存那条。

`.txt` 的解码顺序是 `utf-8-sig` 到 `gbk` 再到 `utf-8` 容错替换。中文 Windows 上的纯文本多半是 GBK。

### 2.2 加密文件拦截

部分环境（如装了 DLP 加密客户端）里，文件在磁盘上带加密头。解析前先读前 16 字节，命中魔数 `%TSD-Header-###%` 就直接抛错，不做解密尝试。

拦它的理由是：不拦的话 python-pptx 与 pypdfium2 会抛 not a zip file 或 corrupted data 这类误导性报错，看起来像文件损坏。网页上传接口在写盘之前就判断，避免在 `out/uploads/` 里堆解不开的文件。

### 2.3 各格式的解析要点

**pptx** 走两遍扫描。第一遍把每页拆成非列表段、列表项与表格三类，列表项按段落级别大于 0 或文本以项目符号开头识别。挑页面标题时先按字号降序，但优先挑像标题的，只有都不像才退回字号最大者 —— 数据展示页的大数字常常压过真标题。

第二遍按字号判定页角色，顺序是目录、分隔页、封面、封底、正文。分隔页的阈值取全文各页最大字号的中位数乘 2.2，不写字面磅值，换模板也不失效。章节标签按位置判定，落在顶部 12% 的带内、字号不超过标题、且匹配编号加文字的形式。分隔页与目录页的其余文字不进正文流，它们的段落只是文本框拼接的产物。

**docx** 按样式名里的 heading 数字取层级。列表按样式或项目符号识别。表格统一追加在末尾，不保留文档内位置。

**pdf** 的信号优先级是书签、编号模式、字号，有书签时不再按版面猜。行高走字符盒高度而不是字号接口，后者在实测的两份 PDF 上一律返回 1.0，标题与正文完全分不开。页眉页脚与页码按出现次数加位置两个条件剔除。正文基线用字符数加权的行高众数，几个大标题动不了它。编号阶梯分五级，从第 X 章一直到多级阿拉伯数字。枚举类编号有护栏，长度超过 20 字或以句末标点收尾的一律不算标题，否则一份制度文件会凭空多出两章。

### 2.4 解析产物

```python
{
  "source": "文件名",
  "kind": "pptx" | "docx" | "pdf" | "text",
  "title": "文档标题",
  "blocks": [...],
  "structure": {...},
  "stats": {"blocks": 120, "chars": 8600},
  "outline": [...]        # 仅 PDF，来自书签树
}
```

`blocks` 有四种类型：

| type | 字段 |
|---|---|
| `heading` | `level` `text` `slide` `role` `ordinal` `subtitle` `kicker` |
| `para` | `text` `slide` |
| `bullets` | `items` `slide` |
| `table` | `header` `rows` |

清理解析结果的规则里有一条要留意：同一标题重复超过 3 次判为页眉只留第一次，但仅在块上没有 `slide` 键时生效。pptx 的重复标题已经被收进章节标签，这条规则对它只会误删。

### 2.5 文档骨架

`structure.build_skeleton` 是纯确定性的，不调模型。章节信号按五级级联，每级都要求至少命中 2 个标记，否则往下一级退化：

| 顺序 | 方法 | 信号 |
|---|---|---|
| 1 | `outline` | PDF 书签树，只取最浅一层 |
| 2 | `divider` | pptx 分隔页与章节标签，取并集 |
| 3 | `depth` | 标题层级，取最浅且标题数不少于 2 的那层 |
| 4 | `numeric` | 显式数字标题 |
| 5 | `flat` | 单章兜底 |

层级排在数字之前是刻意的：层级是解析层给出的事实，数字前缀是猜的。实测一份制度文件里的编号列表项会被数字前缀当成章标题。

空章要丢掉：既没有页单元、也没有正文的章，是书签落在了一个没有标题的页上（实测某份白皮书的第一条书签与下一条落在同一块上，区间宽度是 0）。留着它，大纲会给它编一页正文，分隔页也照插一页。丢完不足 2 章就往下一种信号退化，所以判定看的是丢完之后的章数。书签路径的章名带着代码给的编号，丢掉空章后要重排，否则第一页分隔页上印的是「02」而整份 deck 里没有 01。

书签里的**占位名**（`书签 1` / `Bookmark 1` / `未命名`）不是章节 —— 那是 Acrobat 给没命名的书签自动起的名字。它不当章，它的标题块也不当页单元（否则会被下一章的区间前扩吸收，变成一张标题叫「书签 1」的页）。

骨架的核心概念是**页单元**，即一个标题块加上它到下一个标题之间的全部块。页单元记录源块区间的起止下标、首句与字数。

骨架给下游提供的是**锚点**：

```
源页标题 → 块区间
```

锚点存标题而不存块下标。块下标会被解析器改动，重跑一次解析就全错位。标题人看得懂，也能在大纲里手动改。映射每次从骨架现算，不会过期。取内容优先走锚点，取不到才退回标题精确匹配。

## 三、生成大纲

### 3.1 执行顺序

顺序本身有语义，不能调换：

1. 分章兜底 —— 它改的是章节数，而章节数决定分隔页要占多少页数预算。
2. 扣分隔页预算 —— 分隔页必须先扣掉，而不是等正文按上限生成完了再硬塞。
3. 调用模型生成，或走确定性兜底。
4. 规则插入章节分隔页。
5. 打 `_meta` 标记。

### 3.2 页数预算

页数区间来自 `PPTGEN_MIN_PAGES` 与 `PPTGEN_MAX_PAGES`，**章节分隔页不占这个额度**，它由 `PPTGEN_SECTION_DIVIDERS` 单独控制。

判据是扣掉分隔页之后每章至少还留得下**两页**正文（页数上限 ≥ 章数 × 3），装不下就完全不插，不硬塞也不砍正文。留两页而不是一页：结构页不该把正文压到每章一句话 —— 早先那条线划在「每章一页」，12 页上限配 6 章正好踩线通过，于是无论上传什么文档，出来的都是「六部分、每部分两页」的同一副骨架。扣掉分隔页的同时，正文页数区间的下限也同步下移，避免上下限撞成一个点。

插不插由预算说了算：`_add_dividers()` 收的是 `_divider_budget()` 的结论，判「不插」时一页都不插。早先它只看开关和章数，预算说不插也照插，那条规则等于没生效。

上限是硬执行，靠丢页与丢章。下限只进 warnings，没有补页逻辑。预算小于章数时会整章丢掉，所以分章阶段有提前的护栏。

### 3.3 分章兜底

由 `PPTGEN_OUTLINE_SEGMENT` 控制，默认开。只在这两种情况触发：

- 整份文档只剩 1 章，说明结构信号压根没抽出来
- 章数超过上限，上限取 `min(7, 页数上限 ÷ 2)`，说明层级太碎

模型只做**分组**，不做自由分章。页单元是解析层定下的块区间，锚点体系全靠它们的名字。返回的分组会被严格校验：必须从 1 起、首尾相接、覆盖全部页单元、章名长度合规。不合格整份丢弃，走按页单元均分的兜底 —— 分组错一个就会让某页内容对不上锚点，而不均衡只是不好看。

目标章数由**页数预算**推（`max(2, min(min(7, 页数上限 ÷ 2), 页数上限 ÷ 3))`），12 页上限对应 3–4 章。早先这里写死 3–6 章，而模型每次都取上限 —— 不管文档是 104 章的散架子还是 15 章的规整结构，出口都是 6 章。

关掉这个开关后一次模型调用都不发。

### 3.4 生成方式

源文本超过 24000 字时按章分片，每章一次调用，各自只带该章正文，页数配额按各章源页数比例分配。短文档走一次调用，信息最全也最省钱 —— 但它同样会拿到各章的页数配额（同一套 `_allocate`），写进提示词里，并明说**不必均等**。没有这个信号时模型的默认解是最省事的均分：6 章 6 页，每章一页。

章节划分以骨架为准，提示词里明写一章不少、不改名、不合并。骨架为空时才允许模型自行分成 3 到 5 章。

### 3.5 提示词里的硬约束

**标题长度是版面事实**，超了会被压行或截断：

| 对象 | 上限 | 版面依据 |
|---|---|---|
| 整份 PPT 标题 | 20 字 | 封面占位符 6.18 乘 2.16 英寸 |
| 章节名 | 14 字 | 分隔页 7.73 英寸宽的一行 |
| 页面标题 | 24 字 | 正文页眉 11.33 乘 0.62 英寸 |

骨架给出的章节名要原样照抄，连中英之间的空格一起。骨架里的破折号之后是该章副题，不是章节名的一部分，副题信息放进 summary。骨架摘要里章名与副题分两行写，就是为了让模型没有整行可以抄。

每页的 `intent` 必须从 11 个固定值里原样选一个：`statement` `definition` `enumeration` `comparison` `process` `timeline` `hierarchy` `quantitative` `status` `summary` `quote`。自创或写中文就无法映射到候选版式。

内容取舍口径由 `PPTGEN_CONTENT_MODE` 决定，三个值各有一个人看的说法（界面上显示的、`.env` 注释里写的、README 表格里列的，都是这一套）：`strict` = **严格参照文档**（只做结构整理），`balance` = **适当扩展内容**（允许合并提炼但数字与专有名词必须保留），`enrich` = **大量拓展内容**（可以补写过渡）。值仍用英文口径名传给提示词，改名只动显示文案。这一条注入分章提示词与一次性大纲提示词两处，**按章分片那条路径不读它**，长文档永远按平衡口径生成。

网页把这个口径做成了「内容策略」下拉（`web/index.html`），一次流程一个选择，不必改 `.env` 再重启服务。覆盖走 `config.content_mode_override`，挂在**任务线程的局部变量**上（`server._spawn` 里进入、线程结束即消失）：`.env` 一个字不改，两个任务并发跑时各用各的口径，CLI 那一侧也永远只读 `.env`。请求里没带或带了个不认识的值都退回 `.env` 的默认值 —— 与非法 `.env` 值的处理一致。

### 3.6 校验、重试与修正

生成后过一遍校验清单：章节数是否与骨架一致、正文页数是否落在区间内、每页是否有展示形态与来源标注、意图是否合法、标题是否退化成空标题或重复。

发现问题就带着违规清单重试一次 —— 模型对页数区间这类硬约束经常第一轮不当回事。重试仍不合格则走确定性修正：补齐缺失字段、按骨架校正章节，超页时按比例压缩并均匀抽页。**不退回兜底**，兜底更差。

修正做了什么会记进 `_meta.warnings`。

### 3.7 兜底路径

章节直接沿用文档骨架。早先按标题的数字前缀分组，而章节号在分隔页上是独立块，于是全部落进同一个分组压成 1 章。

每个页单元成一页，锚点就是页单元名，意图用关键词表加内容形态猜。一个章节都分不出来时退回每个标题一页的单章形式。

### 3.8 大纲 JSON 结构

```jsonc
{
  "title": "整份 PPT 的标题",
  "sections": [{
    "name": "01 初识 Dify",
    "summary": "一句话概括",
    "pages": [{
      "title": "页面标题",
      "hint": "展示形态",
      "intent": "definition",
      "source": "Source: ...",
      "anchor": "该页内容来自的源页标题",
      "divider": true,      // 仅分隔页
      "num": "01",          // 仅分隔页
      "lead": "一句导语"     // 仅分隔页
    }]
  }],
  "toc": ["01  初识 Dify  什么是 Dify、设计初衷与九大核心理念"],
  "page_count": 12,
  "_page_range": [9, 12],
  "divider_count": 5,
  "total_pages": 17,
  "_meta": {
    "generated_by": "llm",
    "model": "deepseek-flash",
    "warnings": []
  }
}
```

目录行按宽度裁剪而不是字数，宽度上限 9.50 英寸，取自模板目录占位符减去内边距与悬挂缩进。裁剪走宽度折行，不逐字切，不会把 LLMOps 劈成 LLM。

落盘位置是 `out/plans/<stem>.outline.json`，同名 `.md` 供人审阅。

## 四、规划与版式

### 4.1 版式库

内置共 19 套，全部画在模板的 `Blank` layout 上。版式库里还可能有自定义版式（见 4.1.1）。

| 版式名 | 含义 | 适合的内容形态 |
|---|---|---|
| `section_divider` | 章节隔断 | 每章第一页，几乎全留白 |
| `statement` | 大字陈述 | 开篇、章节引言、一句话主张 |
| `stat_hero` | 单焦点大数字 | 一个数字压倒一切的指标页 |
| `kpi_grid` | 等权指标卡网格 | 3 到 6 个同级指标 |
| `definition` | 术语定义 | 解释一个概念或名词 |
| `numbered_columns` | 分栏编号列表 | 并列要点、功能清单 |
| `tinted_bands` | 通栏浅色带 | 场景分类、并列陈述 |
| `quadrant` | 四象限 | 四个正交维度，正好 4 条 |
| `comparison_rows` | 维度对照表 | 前后对比、优劣对比 |
| `split_main_aside` | 主区加辅区 | 一页讲两件事 |
| `process_chain` | 横向流程链 | 3 到 5 步操作步骤 |
| `phase_grouped_flow` | 阶段分组流程 | 节点多、标签长、可分组 |
| `timeline_vertical` | 纵向时间线 | 5 到 8 步，有时间推进感 |
| `layered_stack` | 分层架构 | 技术栈、系统架构 |
| `data_table` | 原生表格 | 参数对比、类型矩阵 |
| `metric_trend` | 原生图表 | 趋势、对比、占比 |
| `progress_checklist` | 状态进度清单 | 项目进展、整改落实 |
| `executive_summary` | 结论先行 | 章节小结、汇报收尾 |
| `quote` | 引语 | 结语、核心观点 |

版式元数据的唯一真相来源是 `layout_spec.REGISTRY`。渲染函数与元数据用同一个装饰器注册，写在同一个地方，因此不会漂移。喂给模型的目录、压文案的预算、候选收缩的容量约束全部从这一份派生。

### 4.1.1 自定义版式（从截图添加）

上面 19 套是**内置**的，渲染函数写在 `layouts.py` 里。版式库里还可以有**自定义**版式：由用户上传一张 PPT 版式截图，视觉模型识别出版面结构，程序渲一版试片给人看，人只需要决定采用或放弃。

**自定义版式是声明式的，不是代码。** 一份 `layouts_custom/<名字>.json` 描述「版面上有几个区块、每个区块放什么内容」：

```json
{
  "name": "left_hero_stack",
  "roles": ["content"], "intents": ["enumeration"],
  "min_items": 2, "max_items": 4, "item_chars": 22,
  "blocks": [
    {"kind": "text",    "field": "lead",  "x": 0.67, "y": 2.00, "w": 4.31, "h": 2.53, "size": 30},
    {"kind": "bullets", "field": "items", "x": 5.88, "y": 2.00, "w": 6.12, "h": 4.60, "ncol": 1}
  ],
  "sample": {"lead": "一句话主张。", "items": [{"name": "要点", "desc": "说明"}]}
}
```

区块坐标是**英寸**（`normalize_blocks` 把识别结果的「比例」换算过来）。九种区块：`text` 文字、`bullets` 要点列表、`columns` 分栏卡片、`kpi` 指标卡、`table` 原生表格、`steps` 横向流程链、`rows` 维度对照行、`rule` 发丝线、`band` 通栏色带。

**三条设计决定：**

- **只渲纯文本，不支持段内混排。** 段内混排要求逐 run 折行，而量宽是按纯文本算的，两者对不上就是溢出。强调靠区块自身的 `color`（如 `{"kind":"text","color":"RED"}`）。
- **字号由程序的 `fit` 阶梯决定，不由模型决定。** 模型只给框；写多了降字号，再不行才截断（记进 `TRUNCATIONS`，可听见）。
- **高度一律自适应**：`rh = min(上限, 可用高度 / 条数)`，与内置版式同一套教训（`comparison_rows` 早先用固定行高，4 行时越出画布）。

**入库前的闸门**（用户不能对话修正，所以必须自动跑完）：

1. 归一化 + 校验（名字合法、意图在枚举内、降级链不悬空、样例给全字段）
2. 渲一页试片 → 几何检查零 error、无 `text_overflow` / `text_overlap`、**无截断**
3. 把「原图 + 试片」一起发给视觉模型，判**版面分区**是否复现（几栏、各区块位置与相对大小）
4. 任一步不过就带违例清单重试（默认 2 轮），仍不过就**不入库**，界面显示原因

第 3 步只拦**结构性**差异。装饰性差异（页面里嵌的截图及其区域、序号前的底色块、
图标、字体配色微差）是声明式渲染的必然结果，不是「版式没认出来」—— 一并拦下的
话，「左文右图 + 序号带底色块」这类页面永远入不了库。比对返回的 `kind`
（`structure` / `detail` / `none`）用来区分两者，`detail` 记进草稿备注给人看、不阻断。

识别提示词里也写明：**页面里嵌的截图/图片/图表不要建区块**（版式描述的是版面结构，
图区内容属于内容），序号前的底色块/徽标也不要单独建块 —— 否则模型会为图区建一个
渲不出来的区块，试片必然对不上。

**识别为什么可能失败**，三类原因会逐轮记进草稿并由界面显示：

| 类别 | 典型原因 | 该改什么 |
|---|---|---|
| 声明不合规 | 意图不在枚举内、降级链指向不存在的版式、样例缺字段、名字非法 | 提示词的契约，或让模型重试 |
| 试片不合格 | 几何 error、文字装不下、**有截断** | 区块的框给小了 / 示例文案太长 |
| 构图不一致 | 分栏数、区块位置或相对大小对不上（**仅结构性**） | 识别提示词看漏了分区 |

其中「模型调用失败」这类要留意**解析宽容度**：实测服务端会把 `response_format`
回显进正文（`{"type": "json_object"}` 单独一行，后面才是真正的 JSON），取「最外层
大括号」会把两者跨成一个非法 JSON，整轮作废 —— 解析得从每个 `{` 起逐个试。

**这条路不兜底。** 不合格就是不合格，不会退回某个内置版式顶上 —— 那等于把一份
用户没批准的版式塞进库里。这与修订阶段的口径一致。

**注册要同时写四处**，缺一处就是静默失效：`layouts.LAYOUTS`（渲染分派）、`layout_dsl` 的区块声明、`layouts.LAYOUT_NAMES`（规划阶段的合法性判据）、`layout_spec.REGISTRY`（元数据）。`layout_store.register()` 把这四件事收在一处。

**禁用不等于删除。** `layouts_custom/_state.json` 里的 `disabled` 对内置与自定义一视同仁：被禁用的版式不进候选、不进喂给模型的目录，但渲染函数还在 —— 旧 PPT 照样能渲染、能按页修改。删除只对自定义版式开放。

### 4.2 三段式版式选择

让模型在版式库里盲选，是版式错配的温床。改成三步：

**第一步，定意图。** 有模型时取大纲给的 `intent`。无模型时用关键词表猜，按固定优先级匹配标题与展示形态，都不中就看内容形态：有表格归为数据指标，条目少于等于 2 条归为单点主张，否则归为并列列举。

**第二步，收窄候选。** 纯程序执行：

- 内容形态由 `shape_of` 从源块算出，**不听模型自述**。输出条目数、是否有表格、是否有数字、单条最长字数等。
- 章节页只保留结构类版式，不参与内容驱动的选择，直接返回。
- 按意图过滤：版式声明的意图集合里没有这个意图就剔除。
- 按容量过滤：条目数不在区间内剔除，声明了需要表格或需要数字而实际没有的剔除。
- **不按单条字数筛**。源条目天然是一整句，而版式的单条预算是针对成品的。早先拿源条目长度卡候选，版式被筛得只剩 `statement`。单条字数改为事后校验成品。
- 排序时以该意图为主职的版式排前面 —— 没有这一步，候选顺序就只是作者写渲染函数的顺序。
- 取前 4 个。

**第三步，候选内终选。** 分批送模型，每批 6 页。一次让模型输出十几页完整定义会超出输出上限，JSON 被截断后解析失败，实测 19 页一次性规划直接退回了兜底。

模型看到的每一页都带着这一页的候选集，提示词明写版式必须从候选里选。章节分隔页从不经过模型，它是结构页，没有内容可依据。

### 4.3 护栏

**即时护栏**，每批回来后立即执行：

- 模型选了候选外的版式。**不能只把版式名改掉** —— 字段是照着另一个版式填的，改名会缺键、渲染时才炸。这一页改用确定性生成。
- 条目数超容量。再渲染就会被静默截断成残句。同样改用确定性生成。

**相邻去重护栏**在全部批次回来后统一跑，因为相邻判断跨批。相邻两页版式相同就换成候选里的另一个；候选用光了就从可裁剪的版式里借一个，裁掉两条也好过连着三页同一种构图。

**收尾**校验版式名，未知的换成 `statement` 并写日志。逐页回填页眉三件套，**仅当字段为空时**回填。`statement` 没有标题位，会把 `title` 弹掉。分隔页不给章节标签，它自己就是章节名。目录行为空时按章节兜底生成，否则模板自带的议题一二三会留在成品里。

### 4.4 兜底路径的版式

无模型时只用 8 个能确定性构造的版式。别的版式需要模型才有的信息，比如状态、层级名、图表序列值，硬凑出来就是编造，宁可不用。

确定性选择的分支按条目数走：无条目归为陈述，有表格且条目不超过 5 条走主区加辅区，条目不超过 2 条走陈述，正好 4 条走四象限，3 到 5 条且看起来像步骤走流程链，不超过 9 条走分栏编号，否则走时间线。选择时优先挑本次没用过的版式，避免整份退化成一个版式。

## 五、构建 pptx

### 5.1 组装流程

**核心约束：所有新增页必须在删页之前完成。** python-pptx 按现有部件数量推算新页文件名。先删模板内容页再新增，新页会与既有封底撞名，产出 zip 内两个同名条目，PowerPoint 表现为需要修复或显示错页，而模板封底会被静默覆盖丢失。结构自检把这条固化成了可回归的断言。

1. 打开模板，取得 `Blank` layout。
2. 全部新增正文页，页码从 3 起自动分配，封面 1、目录 2、封底不编号。
3. 删掉模板自带的空内容页。
4. 重排为封面、目录、正文若干、封底。
5. 填封面与目录。
6. 存盘，跑结构自检。

各类页面的处理：

| 页面 | 处理 |
|---|---|
| 封面 | 用模板原页。标题按可用宽自适应字号，过长折两行不截断。标题为空则整个封面都不动 |
| 目录 | 用模板原页。只写文字，字号颜色对齐项目符号全部继承模板版式。条目为空也必须调，否则模板自带的议题一二三会留下 |
| 章节分隔页 | 不是特殊分支，就是普通正文页 |
| 正文页 | 全部用 `Blank` layout，内容由绘图原语按固定坐标画上去 |
| 封底 | 原样保留，只在重排中移到最后 |

结构自检查四件事：zip 内是否有重名条目、是否有多个页标识指向同一部件、每页的关系能否解析、图片关系指向的内容是否为空。

### 5.2 模板继承

整份 deck 就是打开模板得到的，不是新建空白文档再导入主题。正文页复用模板的 `Blank` layout，母版上的品牌元素自动继承，但不使用 layout 上的任何占位符。

模板自带的封面、目录、封底三页被保留并原地填空，**只覆盖字号与中文字体**，颜色、对齐、加粗、行距、项目符号全部继承模板。早先手写样式把模板的白色标题改成深色压在深灰通栏上，几乎看不见。

用 layout 名确认封面与目录的身份，这是模板换版的哨兵：模板换版时在这里直接抛错，而不是把标题静默填到别的页上。

### 5.3 超长文案的处理

优先用折行换字号，不截断。字号阶梯挑最大的一个使文字装进框内且不超过行数上限；阶梯全试完仍装不下才截断，末行加省略号。

截断是**静默**的：它消除了溢出，几何检查全绿，问题只在肉眼看渲染图时暴露。所以每次截断都记进 `TRUNCATIONS`，构建时写进日志。这个机制和版式的单条字数上限，都来自同一个实测案例：一套已删除的版式 8 个节点里 6 个被截成残句，而几何报告是干净的。

宽度估算里有一套修正：破折号、间隔号、省略号这些码点在 CJK 字体里是全角，但码位较小。早先一律按半角算，宽度被低估 5 到 8 个百分点，两行折到贴边时就溢出。

## 六、渲染与 QA

### 6.1 渲染工具

渲染靠外部命令行工具 officecli，不是 Python 库。找不到就跳过渲染，不影响成品生成。

| 用途 | 命令 |
|---|---|
| 逐页 PNG | `officecli view <pptx> screenshot --page N -o <out>` |
| 缩略图联系表 | `officecli view <pptx> screenshot --grid 3 -o <out>` |

原生渲染模式失败时会退回不带该参数重跑一次，但分辨率参数必须回带，否则会静默掉回默认值。

子进程统一按 UTF-8 容错解码。中文 Windows 上按系统编码解码，路径含非系统编码字节时会抛异常。

### 6.2 分辨率

网页逐页预览用 `PPTGEN_PREVIEW_WIDTH` 与 `PPTGEN_PREVIEW_HEIGHT`（默认 1920×1080，已是原生渲染上限）；AI 看图固定 1280×720，不受这两个变量影响 —— 图要转成 base64 塞进视觉模型，像素翻倍等于请求体积翻倍。渲染耗时取决于渲染进程启动，与分辨率无关。

### 6.3 输出路径

```
out/visual/<deck名>/
├── page-01.png              逐页预览图
├── page-12-576a63a4.png     改动前快照
├── contact-sheet.png        缩略图联系表
├── .pages.json              渲染清单
└── .pages.json.tmp          原子写的临时文件
```

网页取图走 `/preview/<stem>/<文件名>`，快照放在同一目录即可零改动取到。

### 6.4 按页指纹与缓存

早先是整目录级的指纹，而构建没有增量能力，于是改一页等于重渲全部，约 3 分钟。现在按页记指纹。

每一页的像素由什么决定：

| 页 | 决定因素 |
|---|---|
| 封面 | 标题，以及生效后的副标题 |
| 目录 | 目录条目 |
| 正文 | 对应的那一条规划定义 |
| 封底 | 常数 |

指纹是这一页的决定因素加分辨率标识的 SHA1。分辨率必须进指纹，否则改了分辨率旧图不会失效。

整份作废有四种因由：没有渲染清单、分辨率变了、模板文件变了、清单损坏。前三种会明确打印原因。

逐页比对，指纹一致就保留，不一致才重渲。页数变少时多出来的旧图会被删掉，否则页面会多出上一版的图。

**渲染失败的一页绝不记入清单。** 记了就再也不会重渲，用户会一直看着旧图而日志正常。

清单用临时文件加替换的方式原子写入。写失败只打印警告，后果是下次整份重渲，必须可见。

清单里记的只有确实是最新的页：本次渲成功的，或本次压根不需要渲的。清单还记这份图是哪份规划产物渲的，供定位兜底。

### 6.5 几何检查

纯程序化，不需要渲染。默认跳过封面、目录与封底，它们的字号与占位符几何由模板决定，报出来只会淹没有效信号。

八类检查：

| 检查项 | 级别 | 判据 |
|---|---|---|
| `out_of_canvas` | error | 包围盒越出画布 |
| `absurd_size` | error | 形状尺寸超过画布 1.2 倍，用于抓单位换算错误 |
| `past_safe_area` | warn | 侵入右侧 12.00 英寸之外的装饰弧线区 |
| `font_below_floor` | error | 任一文本块字号低于 12 磅 |
| `text_overflow` | warn | 估算高度超过框高 6% 以上 |
| `textbox_margin` | warn | 文本框左右内边距不为 0 |
| `text_overlap` | warn | 两个含文字形状在横纵方向交叠均超过 0.05 英寸 |
| `large_empty_area` | warn | 最大连通空白块占比超过 42% |

估算高度按每个文本块各自的字号累加宽度，再折算行数。早先按段内最大字号算整串宽度，会把 72 磅数字加 22 磅单位的混合段算宽一倍，产生误报。

空白占比这一项是生硬感的可执行代理指标。表格与图表没有文本框但确实是内容，早先只统计含文字形状，导致三个表格页被误判为 75% 空白。

报告落 `out/reports/<name>.geometry.json` 与同名 `.md`。

### 6.6 修复回环

未配置模型直接跳过。

每轮构建一次、跑一次几何检查，收集文字溢出、文字重叠、越出安全区三类问题，交给模型整页重写。**不做字段级映射** —— 几何报告里只有形状名，回溯到规划字段既脆弱又易错。

三道接受门槛：模型没返回对象则跳过，版式被改掉则跳过，文本总长度没变短则跳过。只有确实变短才接受。

轮数上限由 `PPTGEN_REPAIR_ROUNDS` 定（默认 3，给 0 就是不修），**界面和请求体都改不了它** —— 它只决定最坏情况下多花几次模型调用（每轮溢出几页就调几次），属于部署口径；要针对某次命令改，用 `run.py repair|full --rounds N`。轮数是**上限**而非固定值：某一轮几何检查已经干净就提前停。

### 6.7 AI 看图

两级策略：

**第一级，整份粗看。** 渲一张缩略图联系表，一次调用让模型整份扫一遍。这一步是抓生硬感的关键：几何检查能查出硬伤，查不出不难看但没设计感，只把几何告警的页送去细看就永远看不见最想解决的问题。

**第二级，逐页细看。** 取第一级判定不通过的页，加上几何检查报过的页，去重后渲成大图，连同同一条提示词再发一次。

模型对每一页回一行 JSON，通过的也要输出：

```json
{"page": 3, "verdict": "pass"}
{"page": 4, "verdict": "fail", "issues": [{"category": "Design", "problem": "...", "evidence": "..."}]}
```

类别限定为规范、内容、视觉、设计、未验证五种。提示词要求按投影距离看：一眼能否读懂、文字有没有压到卡片边缘、单个容器是否一半空着、跨页是否一致。明确禁止泛泛的美化建议。

**没有可用的视觉模型时不报错**，改为输出人工复核包：联系表加评审提示词写成 markdown，连同单页图目录交给人看。模型名在黑名单里的会被直接判定为没有视觉能力，免得返回一堆无法解析的文字、看起来像看图通过。

视觉模型配置留空时，可以回退复用文本模型的连接信息，由 `PPTGEN_VISION_FALLBACK_TO_LLM` 控制。

## 七、生成后的改动

### 7.1 页码约定

```
预览第 N 张 = pptx 第 N 页 = slides[N-3] 下标 = 几何报告里的页码
```

| 预览页 | 是什么 | 小范围修改 | 整页重做 |
|---|---|---|---|
| 1 与 2 | 封面与目录 | 可改标题、副标题、目录条目 | 支持：重出文案，仍用模板页（不换版式） |
| 3 到 n-1 | 正文页或章节分隔页 | 可改字段值 | 正文页可换版式，分隔页只能微调章节名与导语 |
| n | 封底 | 不支持，没有可改内容 | 不支持，没有可改内容 |

这份映射只在 `revise.build_page_index` 里实现一次，前端只显示不算，喂给模型的页码表也是它生成的，不让模型自己数页码。规划产物里混着章节分隔页，实测某份 15 页的成品里 5 页是分隔页，所以正文第 5 页与预览第 5 张能差出好几页。

### 7.2 输入的解析

用户在一个输入框里写自然语言，可以写多条，说明哪几页要怎么改。

先由程序生成一张页码表摊给模型：预览号、这一页是什么、版式、页面上的大字、可改字段，明令模型只回预览号这一个数。

解析结果分两类：页码不是整数、或不在清单里的，进未识别列表并附上页数；解析不出任何条目则直接报错。**不猜也不夹取。**

### 7.3 两种模式

模式是对整个输入框生效的。

**小范围修改** 只改字段值，版式不变。路径表由这一页的实际数据推导，**里面根本没有 `layout` 字段**，所以版式不改变成了结构上的不可能。

每条补丁都要回带该路径**当前的值**：

```json
{"path": "items[2].desc", "expect": "成本下降三成", "value": "成本下降 30%", "why": "..."}
```

现值比对拦的是本模式最危险的失败：模型把第二条按 1 基理解、指着第一条，补丁完全合法、会静默落盘、改错了条目。

路径只开放到元素这一层，再往下拆会破坏富文本或表格结构，一律拒绝。

三档校验，从便宜到贵：路径与类型与条目数、现值比对、预演构建。**第三档才是真正的容量门**，前两档挡不住大多数溢出。

**整页重做** 这一页重讲，**可以换版式**、重挑内容。走的是规划阶段的分批接口，不复用修复回环的整页重写 —— 后者的三道护栏全部指向压缩，而换版式与变长正是重做的核心。

版式候选**不锁意图**：用户说换成能对比的形式时，锁在原意图的候选里根本选不到对照表。同时禁用相邻页正在用的版式。

**封面与目录是例外：它们没有版式可换。** 那两页就是模板自己的第 1、2 页（`build.fill_cover` / `fill_agenda` 往占位符里写字），所以重做在它们身上退化成**重出这一页的文案** —— 模型看着整份大纲重拟封面的标题、副标题，重写目录条目，版式与品牌元素一个不动。落盘走的是与微调**同一条**路径（`check_ops` → `apply_ops` → `commit_page`），于是补丁、大纲同步、面板上的逐条 diff 全都不用另写一套；区别只在谁出这份补丁：微调是用户指名路径，重做是模型重拟。

两条约束写死在 `revise.check_template_new`：**目录条数必须与原来一致**（一条对应一个章节，增删会让目录与分隔页对不上，直接拒），**封面标题 20 字**（超了 `fill_cover` 先折行再缩字号，全试完仍装不下就静默截断，所以超了只提醒、但一定说出来）。这两页**不在几何检查范围内**（`qa/geometry.py` 默认跳过第 1、2、n 页），宽度只能靠 `_toc_line` 夹取 —— 夹过的条目会在方案里逐条写明。

两轮重试，仍不合格则确定性降级，并把原因原样带回给用户，降级是听得见的。

### 7.4 每次提交的上限

`PPTGEN_REVISE_MAX_PAGES` 默认 3，**只在整页重做模式生效**，小范围修改不受影响，因为所有条目合并成一次调用。

存在的理由是模型调用没有取消接口，单次最坏 9 分钟，而重做是一页一次调用。用户写五页都重做就是五次，最坏 45 分钟且中途停不下来。

超出的条目不会被静默丢掉，会明确回一条本次没做、请再提交一次。

### 7.5 两阶段：先提案，后应用

**提案阶段一个字节都不写盘**，除了一份草稿，供刷新页面后还能接上。

面板上把每条改了什么逐条列出来，标量的新值还能直接手改，确认后才应用 —— 自然语言改稿最容易崩的地方就是它到底动了哪几个字。

被拒的条目不影响其余，并给出人能看懂的原因。

应用阶段前端把可能被手改过的方案原样回传，服务端**不重调模型**。

### 7.6 应用时的校验与重建

1. **乐观并发**：比对规划产物的内容指纹。指纹筛掉了页码键与下划线开头的键，因为构建会原地往每条定义里写页码，用文件时间戳判断每次都会变。指纹对不上说明这份产物在生成方案之后被改过，直接拒绝并提示重新生成方案。
2. 再查一遍是否有本版已不认的版式，有就整份拒绝 —— 直接改会静默换掉用户正在看的那一页，比拒绝更糟。
3. 整页重做按顺序**增量应用**：先把前一页写回，再算后一页的禁用版式。否则用户写第 5、6 页都重做时会同时选到同一版式。
4. **预演构建加几何检查**，只看改变了的页，只挑文字溢出、文字重叠、越出安全区三类硬问题。构建加检查约 1 到 2 秒，而渲染要 8 到 10 秒，所以每次都跑。封面与目录**不在这道门里**（几何检查默认跳过第 1、2、n 页），它们的长度由字数预算与目录宽度夹取守，越界的条目在方案里就写明。
5. 没通过预演的页交给修复回环的单页版本处理，冻结版式只压短。**不跑整份修复回环**，那会把用户没让改的页一起重写。
6. 落盘规划产物，重建 pptx，写几何报告。
7. **只重渲改动的页**，按 6.4 那套按页指纹决定。
8. 没渲上的页必须说出来，会警告页面上这几张仍是旧图、请检查渲染工具是否可用。

### 7.7 改动的真相来源

| 改什么 | 落到哪 | 会不会被覆盖 |
|---|---|---|
| 正文页内容字段 | `<deck>.deck.revised.json` | 安全 |
| 正文页标题、章节标签、来源标注 | 同上 | 安全，收尾回填只在字段为空时生效 |
| 目录条目、封面标题与封面副标题 | **必须同时写 `<name>.outline.json`** | 会被重算（`cover.title` / `cover.subtitle` / `toc` 三条补丁，两种模式都产生） |

最后一行还有前端的一半：生成接口的输入是页面上的大纲状态，不是磁盘那份。所以应用之后前端会把大纲补丁合并回去并重渲大纲编辑器 —— 只写盘的话，用户不刷新页面直接点生成还是会被覆盖。

另外生成接口启动时会检查修订台账，有记录就先打一条之前有多少处人工修改、本次重新规划会覆盖掉。台账落在 `out/plans/<stem>.revisions.json`。

### 7.8 已知边界

- **不能改页数**，拆页与删页都不支持。页码映射、按页指纹、模板页删除逻辑都建立在页数稳定上。
- **封面与目录的整页重做不换版式**（它们就是模板的第 1、2 页），也不能增删目录条目 —— 一条对应一个章节。这两页不在几何检查范围内，宽度靠 `_toc_line` 夹取，高度只能靠 `fill_agenda` 的估算与构建日志里的截断提醒。
- **封面副标题不能清空**：空串会被当成「这条没给」（`template_new`），补丁校验也不收空值。去掉副标题目前只能改大纲 JSON。
- **图表数据不支持微调**，改图表请用整页重做。
- **旧版产物会被整份拒绝**。历史产物里可能躺着已删除的版式，渲染时直接抛错，而收尾逻辑会把它悄悄换成 `statement`，那会静默改掉用户正在看的那一页，所以宁可拒绝并让用户重新生成。
- **修订必须有文本模型**。没配时直接失败，不学大纲与规划的兜底 —— 出不了补丁的成功是最坏的静默失败。

## 八、模型调用的超时、重试与降级

### 8.1 超时与重试

总尝试次数是 `PPTGEN_RETRY + 1`，默认 3 次。每次尝试独立计时，超时是 `PPTGEN_TIMEOUT`，默认 180 秒。

请求返回 4xx 时**立即停止重试**，只有 429 例外。其它异常继续重试。

退避是线性的：第一次失败后等 1.5 秒，第二次后等 3 秒。

**单次调用最坏耗时约 9 分钟**，即三次超时加两次退避。这个数字决定了几件事：规划阶段必须有分批进度日志，整页重做必须有页数上限。

### 8.2 空内容的识别

返回内容为空时会检查推理字段与推理 token 计数。命中则报一条明确的错误：模型只产出了推理内容，正文为空，推理占用了多少 token，建议把 `PPTGEN_MAX_TOKENS` 调大或换非推理模型。

**刻意不返回空串**，空串会让上游静默继续。

### 8.3 各阶段的降级行为

| 阶段 | 触发 | 行为 |
|---|---|---|
| 大纲 | 模型报错或结果为空 | 退回确定性大纲，标 `fallback`，打日志 |
| 大纲 | 未配置模型 | 同上，警告文案是未配置文本模型 |
| 规划 | 模型报错或结果为空 | 退回确定性规划，标 `fallback`，打日志 |
| 修复回环 | 未配置模型 | 跳过整个回环 |
| 修复回环 | 单页压缩失败 | 记录并继续下一轮 |
| 修复回环 | 达到轮数上限 | 停止并提示仍有未解决问题 |
| 整页重做 | 单页两次不合规 | 退回确定性生成，并把原因带回给用户 |
| 整页重做（封面/目录） | 模型给不出可用的文案（条数对不上、空标题） | 该条标为不能应用并给出原因，其余条目照常 |
| 修订 | 未配置模型 | **不兜底，直接失败** |
| 识别版式 | 未配置视觉模型 | **不兜底，直接失败**并说明原因 |
| 识别版式 | 声明不合规 / 试片不合格 / 构图不一致 | 带违例清单重试（默认 2 轮），仍不过就**不入库**，逐轮原因带回界面 |
| 看图 | 视觉模型不可用 | 输出人工复核包，不报错 |
| 渲染 | 原生渲染失败 | 退回默认渲染，并且必须回带分辨率参数 |
| 渲染 | 找不到渲染工具 | 跳过渲染，网页返回空图列表 |
| 日志 | 任何写盘失败 | 吞掉异常，只在 stderr 打一条警告 |

兜底的可见性贯穿整个项目。回退产物在大纲与规划里都带标记，会进 run.json、进大纲预览的横幅、进网页的告警框 —— 以前它只打印一行 stdout，界面上和模型产出长得一模一样，结果就是拿着一份兜底大纲当模型产出看。

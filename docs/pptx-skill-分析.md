## 2. 整体能力地图：三条生成路径

这份 skill 不是"一个脚本"，而是**一套决策树 + 设计规范**。它按用户给什么输入，走三条完全不同的路：

```
用户要一份 PPT
├── 路径 A：从零创建 ──────── Part 1 设计规范 → Part 2 pptxgenjs 编码
```

## 3. 设计层：Part 1《Slide Design Best Practices》

开篇定调一句话：**"不要做无聊的幻灯片"**。但紧接着立刻补一句限定：**"不无聊" ≠ "花哨"**——目标是一份能直接丢进真实会议/课堂/客户提案、不用改就能用的 deck。

另一条贯穿全篇的原则：**Substance comes before styling（内容先于样式）**。每页必须承载一个具体、可证的主张（真实数字、名字、机制，以及背后的"so what"），而不是一个话题标签。并且强调：**深度 ≠ 密度**，深度来自"挑最锋利的那一个事实、砍掉其余"，不是堆字。

### 3.1 动手前必须先定三件事

**① 由内容推导的配色**
调色板要"为这个主题而设计"。判断标准很妙：**如果你把这套颜色放进一份完全无关的 deck 里依然"能用"，说明你的选择还不够具体**。颜色应该从主题自身的地域、行业、品牌、情绪里长出来，而不是伸手去拿默认色。

**② 主导，而非平均**
一个颜色占据 60–70% 的视觉重量，1–2 个次级色辅助，一个锐利的强调色。**永远不要让所有颜色等权重**。

**③ 明暗对比 + 视觉母题**
- **三明治结构**：封面/封底用深色背景，内容页用浅色背景；或者全程深色走高级感。
- 选定**一个**标志性母题并在每页重复：圆角图片框、超大数字、统一的卡片处理……
- ⚠️ **严禁**用"色条 / 强调条纹 / 侧边栏色带"当母题——这是 AI 生成幻灯片的典型特征。

### 3.2 色彩系统：BACKGROUND → PRIMARY → ACCENT

固定三角色，**每一页复用同样的三个角色**：

- **BACKGROUND**：中性或近中性底（米白、暖灰、深藏青、近黑），承载 60–70% 画面
- **PRIMARY**：品牌/主题色，用于标题、关键形状、图表柱、结构元素
- **ACCENT**：**唯一一个**高饱和色，克制使用（约占画面 5–10%），只打在最关键的那一个元素上——一个头条数字、一根高亮柱、一条下划线
- **在脚本顶部把调色板定义成常量**（`BG` / `PRIMARY` / `ACCENT` / `TEXT` / `MUTED`），全篇只引用常量，**绝不逐页临时挑色**
- 需要区分度时，**优先用主色的深浅变体（tints / shades）**，而不是新增色相——图表同理
- 页与页之间的色彩变化，只允许是三明治结构带来的背景/文字反转

### 3.3 版式：每页的构成法则

**三条硬规则**：
1. **每页必须有视觉元素**——图片、图表、图示或形状。纯文字页是失败的。
2. **每页必须有一个清晰的视觉焦点**——超大数字、图表、图片或一句粗体陈述，它主导构图，其余全部从属于它。
3. **优先"无容器分组"**（大多数页面都用它）：分组靠**对齐、间距、字重**建立，而不是画个框把东西圈起来。

无容器分组的具体手法：
- **发丝分隔线**（1px 细线，不加粗、不加阴影）
- **行列表**（通栏行、无容器，靠大行距 + 加粗引导词分隔）
- **描边框**（1px 描边，无填充）
- **浅色带**（横向浅色带，左右出血到版心边缘——不圆角、无边框、无阴影）
- **图标 + 文字行**（图标在行左，粗体标题，描述在下；图标放在裸背景或方/圆角方形容器里，**不要用圆形**）

**按页面用途选版式**：

| 页面用途 | 版式 |
|---|---|
| 开场 / 收尾 | 大标题式 |
| 流程 / 工作流 | 编号步骤视觉 |
| 对比 | 并排 或 表格 |
| 数据 / 指标 | 图表为主 + 超大数字 |
| 核心洞察 | 单句强调式 |
| 团队 / 人物 | 并排卡片行（**一行平行卡片，不是网格**） |

**数据展示**（所有字号以 13.33 × 7.5" 画布为基准）：
- 大数字标注：**数字 60–72pt** + 下方小标签
- 对比列（before/after、优/劣、并排选项）
- 时间线 / 流程链（编号步骤 + 箭头）
- **指标要短促有力**——`"$87B TAM"` 胜过 `"Total Addressable Market is $87 billion"`

**密度与节奏**：
- **一页一个核心信息**，层级为：标题 → 副标题 → 正文 → 支撑细节
- **控制每页文字量**——文字过多是溢出的头号原因；要点写成短句短语而非完整句；太重的页面就**拆成两页**
- **留呼吸空间**——文本框要给出足够宽高，让文字**宽裕地**排下，而不是从边到边塞满
- **变化节奏**——交替使用"文字驱动 / 图片驱动 / 数据驱动"的页面
- **不允许大片空白**——用**内容**去解决：放大字号或焦点元素、加宽图表/图片、收紧栅格与边距，或把真实内容（引语、图注、支撑数字）提升到那个区域
- **绝不用无内容的装饰填空白**——没有分隔/分组/强调作用的色块、细条、线条一律不加
- **照片区域不算"空白"**——如果照片区看起来像黑洞，是遮罩太重或图太暗，应该减淡遮罩或换更亮的图，而不是在上面继续堆装饰
- 每页自检：**焦点明显吗？有东西溢出吗？**

### 3.4 图表与图示（强烈推荐）

- **能用图讲就用图讲**——要点列表是**兜底**，不是默认
- 优先选用：示意图/概念图（方框 + 连接线表达架构或关系）、流程图与编号流程链（箭头、时间线）、对比矩阵、数据图表（柱/折线/堆积/环图）
- 目标是**相当大比例的内容页都带图示/流程图/图表**——"全是文字块的 deck 就是失败的 deck"
- **原生构建**（`addChart` 或 形状 + 连接线 + 文本框组合），这样能继承调色板，且**零图片调用成本**
- **给一切打标签**：轴标题、单位、分类、柱/点上的直接数值。剔除图表垃圾——无 3D、无渐变、能直接标注就不要网格线和图例
- **每个关键数字、每张图都要标注来源**：底部 10–12pt 的弱化小字，如 `"Source: IDC Worldwide Tracker, 2025"`
- **绝不把编造的数字伪装成有出处的**；估算或示意数据必须标注 `illustrative` / `est.`

### 3.5 图片与文字的叠层（关键）

- **绝不把文字直接压在满版图片上**——必然不可读
- 用背景图时，**必须在图和文字之间加半透明遮罩**，三步顺序：
  1. 放图（满版，置于底层）
  2. 图上加深色遮罩矩形（满版，约 **60–80% 不透明度**）
  3. 再在遮罩上放文字
- **更优方案**：不用满版图，而是把图放在**有边界的区域**（比如右半版），文字放在另一侧的纯色底上
- 装饰性图片要放小，且避开与文字碰撞
- **绝不拉伸图片**——比例不匹配就裁剪（`sizing: { type: 'cover' }` 或显式 `crop`），**绝不用破坏比例的 `w`/`h` 去硬撑**。封面和满版背景上，拉伸的照片是整份 deck 最显眼的缺陷
- 心算自检：**"如果这页打成灰度，每个字我还能读出来吗？"**

### 3.6 字体排印

- **刻意选择与场景匹配的字体组合，并在方案里写明**：企业/科技/数据类用几何或新怪诞无衬线；编辑、学术、法律、传承类用衬线；高对比展示体**只用在封面**。**绝不留默认字体**
- **每个 run / paragraph 都显式设置字体**（python-pptx 的 `run.font.name`、pptxgenjs 的 `fontFace`），**不依赖主题继承**
- 封面/标题字：**44–72pt**、粗体、有冲击力；内容页正文**约 24pt**
- **全页最小字号**（图注、轴标签、脚注、来源行）**不得低于 12pt**，且与其背景保持高对比
- **可读性 > 装饰**：彩色或图片背景上不用细/极细字重，长文本不全大写，字距不能紧到笔画相撞
- **最多 2 个字族**，层级靠**字号与字重**建立，而不是换字体
- **幻灯片内容中不使用 emoji**

> ⚠️ **预览陷阱（写得很实在）**：你写进 `.pptx` 的字体名是**由用户的 PowerPoint 渲染**的，不是你的构建环境。如果你用 LibreOffice 预览，它会替换掉没有的字体，而**替换后的字宽不同**，导致预览的"溢出/能放下"结论与真实 deck 不一致。**优先选 Office 自带、且本地也能按真实字宽渲染的字体**；做不到的地方，留 **~10% 余量**，不要相信预览。

### 3.7 间距

- 最小页边距 **0.5"**
- 内容块之间 **0.3–0.5"**
- **全篇页边距与间距一致**
- 留呼吸空间，不要塞满每一寸

### 3.8 中文字体专项（CJK）

这一节相当专业，是很多同类 skill 缺失的：

- **要点名用户 PowerPoint 真的装了的字体**：微软雅黑 / 等线（Windows）、苹方 PingFang SC（macOS）。只在构建机上存在的字体（Noto Sans SC、思源黑体、LXGW 文楷……）会在用户机器上**静默替换**，只能作为 fallback，不能作为唯一字体名
- **正文无衬线、编辑感用衬线**：企业/科技/数据 deck 用微软雅黑 / 苹方；文化、学术、传承主题才用思源宋体 / 宋体，且主要用在标题上。**正文绝不用**楷体 / 行楷 / 隶书 / 艺术字体
- **避免 Light / Thin 中文字重**——汉字笔画远多于拉丁字母，发丝字重在投影仪上会糊成一团。正文 Regular，标题 Bold/Semibold；层级靠字号字重，不靠第三个字族
- **中文没有词间空格可断行**，长句会在短语中间换行——所以**行要短**，且 **CJK 文本框要比拉丁等效宽度多留约 15%**。好处是：汉字是等宽的，所以**中文的溢出检查相对可信**
- 默认用宋体或库默认字体，**deck 会瞬间读起来像 Word 文档**——必须像 §3.6 要求的那样刻意选字体

### 3.9 避免清单：AI 味的来源

这是全篇最有价值的部分之一，直接列出了"看起来像 AI 生成"的特征：

| ❌ | 问题 | 正确做法 |
|---|---|---|
| 每页用同一版式 | 单调 | 在分栏、卡片、标注之间变化 |
| 滥用栅格布局 | 2×2、3×2、4-up 卡片网格重复出现是**强 AI 特征** | **上限约每 5 张内容页 1 次**，不得连续两页，且只在内容真的是并列同类项（团队、功能矩阵）时用 |
| 正文居中 | 业余 | 段落与列表**左对齐**，只有标题居中 |
| 字号对比不够 | 标题不突出 | 标题要 **36pt+** |
| 默认用蓝色 | 无主题感 | 选反映主题的颜色 |
| 间距随意 | 不专业 | 选 0.3" 或 0.5"，**一致地用** |
| 只美化一页 | 割裂 | 要么全力做，要么全篇简洁 |
| 纯文字页 | 无聊 | 加图、图表、图示或形状 |
| 文本框内边距 | 对不齐 | 要与形状/线条对齐时，把文本框 `margin` 设为 0（或偏移形状补偿） |
| 低对比 | 不可读 | 文字和图形都要与背景强对比，避免浅配浅、深配深 |
| 🚫 **标题下加装饰性下划线** | 经典 AI 特征 | 用留白或背景色代替 |
| 🚫 **装饰性色条 / 强调条纹** | 包括通栏页眉页脚色带、竖向侧边条、卡片边缘细色条、"单边框"矩形 | 要让卡片突出，用**微妙的背景浅色调或阴影**，不用边缘条纹。尤其**不要在连续多页重复同一套边缘条处理** |
| 默认奶油/米色背景 | 无指定时的偷懒默认 | 未指定时用纯白 `FFFFFF` 或品牌色；避开 `F5F5DC`、`FAF0E6`、`FAEBD7`、`FFF8E1` 这类暖中性默认色 |
| 文字溢出形状 | 明显缺陷 | 缩字号、拆页、或放大容器；绝不留被裁掉或溢出的内容 |
| 无故对东亚字体做额外后处理 | — | 不需要就别动 |

### 3.10 QA（推荐流程）

- **内容 QA**：查漏、错别字、顺序错；用模板时 grep 残留占位符（`xxx`、`lorem`、`TODO`、`[insert` 等）
- **代码 QA**：写一段短 python-pptx 脚本扫成品，标记**文本溢出**（估算文本高宽 vs 形状框，以及超出画布的形状）和**重叠**（两个含文字形状的包围盒相交），修掉真问题后重跑
- **视觉 QA 只做一次**：用 `pdftoppm` 把 pptx 转图，必要时用 judge 子代理检查（没有的话自己看）。**明确禁止调用外部 VLM 来检查幻灯片**——这条很关键，等于把"视觉验证"限制在本地可控范围内

## 4. 实现层：Part 2《pptxgenjs in Depth》

### 4.1 画布与常量（第一原则）

```javascript
const pptxgen = require("pptxgenjs");
let pres = new pptxgen();
pres.layout = 'LAYOUT_WIDE';   // 13.33 × 7.5"

const W = 13.33, H = 7.5, M = 0.5;   // 宽、高、页边距
// 所有坐标由常量推导，绝不硬编码 10 或 13.33
```

| Layout | 尺寸 |
|---|---|
| **`LAYOUT_WIDE`** | **13.33 × 7.5 —— 用这个** |
| `LAYOUT_16x9` | 10 × 5.625（pptxgenjs 默认） |
| `LAYOUT_16x10` | 10 × 6.25 |
| `LAYOUT_4x3` | 10 × 7.5 |

> ⚠️ 这段警告写得很到位：pptxgenjs **默认是 `LAYOUT_16x9`（10 × 5.625"）**，而本 skill 所有字号规范（44–72pt 标题、~24pt 正文、60–72pt 数字）都是按 **13.33 × 7.5"** 调的。不显式设 `LAYOUT_WIDE`，就等于在**窄 25%、矮 25%** 的画布上装大画布的字号，**系统性溢出**。如果确实要做 10" 宽版式，所有字号和 0.5" 边距**同比例 ×0.75**。
> （注：真实宽度是 13.333"，写 13.33 是为了保证不越界。）

### 4.2 文本与格式化

```javascript
// 字符间距：用 charSpacing（letterSpacing 会被静默忽略）
slide.addText("SPACED TEXT", { x:1, y:1, w:8, h:1, charSpacing: 6 });

// 富文本数组（一段内混合样式）
slide.addText([
  { text: "Bold ",   options: { bold: true } },
  { text: "Italic ", options: { italic: true } }
], { x:1, y:3, w:8, h:1 });

// 多行：每行都要 breakLine: true（最后一行可省）
// 文本框内边距：margin: 0 才能与形状/线条对齐
slide.addText("Title", { x:0.5, y:0.3, w:9, h:0.6, margin: 0 });
```

**⚠️ 一个非常硬核的坑（富文本 `<a:pPr>` 问题）**：

> 富文本数组会**为每个 run 生成一个 `<a:pPr>`，而不是每段一个**。两个及以上**不带 `breakLine`** 的连续项会落进同一个 `<a:p>`，各自带一个 `<a:pPr>`——这违反 `pPr? (r|br|fld)* endParaRPr?` 的 schema。**LibreOffice 渲染正常，所以 PDF 预览抓不到**；PowerPoint 会先正确绘制，然后重新排版该段落，**这一行就乱了**。
> 两个安全做法：① 每项都给 `breakLine: true`（一段一 run）；② 确实需要行内混排时，`writeFile()` 后**后处理幻灯片 XML**，把每个 `<a:p>` 内第一个之后的 `<a:pPr>` 全部删掉。
> **不要**用"拆成两个段落"来绕过——那会把一行行内混排悄悄变成两行，破坏你设计的版式。

这段是典型的"只有踩过坑才写得出来"的经验，价值很高。

### 4.3 列表与项目符号

```javascript
// ✅ 正确：多项 bullet
slide.addText([
  { text: "First item",  options: { bullet: true, breakLine: true } },
  { text: "Second item", options: { bullet: true, breakLine: true } },
  { text: "Third item",  options: { bullet: true } }
], { x:0.5, y:0.5, w:8, h:3 });

// ❌ 错误：绝不用 unicode 圆点（会产生双圆点）
slide.addText("• First item", { ... });

// 子项与编号列表
{ text: "Sub-item", options: { bullet: true, indentLevel: 1 } }
{ text: "First",    options: { bullet: { type: "number" }, breakLine: true } }
```

**让项目符号好看**（默认 `bullet: true` 很业余）：

裸的 `bullet: true` 会渲染出一个**巨大的圆点 + 到文字的超大间隙**（pptxgenjs 默认约 **27pt 悬挂缩进**）——典型的 AI 列表特征。必须手动造型：

```javascript
// bullet 是【段落】属性 —— 要放进【每一项】的 options 里，不是顶层。
// 顶层的 bullet 只会给第一段造型，其余段落变成 <a:buNone/>（没有圆点）。
const bu = () => ({ code: "2022", indent: 14 });  // 工厂函数：每项一个新对象
slide.addText([
  { text: "First item",  options: { bullet: bu(), breakLine: true } },
  { text: "Second item", options: { bullet: bu(), breakLine: true } },
  { text: "Third item",  options: { bullet: bu() } }
], {
  x:0.5, y:0.5, w:8, h:3, fontSize: 15, color: "334155",
  paraSpaceAfter: 8,   // 项间距（不要用 lineSpacing）
  margin: 0,           // 让字形对齐 x
});
```

- **`indent` 最关键**——把默认 ~27pt 砍到 **10–16pt**，消除"漂浮的圆点"
- **更精致的字形**：`2022`(•)、`25AA`(▪)、`2013`(–)、`25B8`(▸) 比胖圆点更有设计感；颜色调弱（如 `94A3B8`）保持克制
- **短卡片列表**（3–4 项）：**别用原生 bullet**，改为**每行一个小色点/方块形状 + 一个文本框**，获得完全控制

### 4.4 形状

```javascript
slide.addShape(pres.shapes.RECTANGLE, {
  x:0.5, y:0.8, w:1.5, h:3.0,
  fill: { color: "FF0000" }, line: { color: "000000", width: 2 }
});
slide.addShape(pres.shapes.LINE, { x:1,y:3,w:5,h:0, line:{color:"FF0000",width:3,dashType:"dash"} });
slide.addShape(pres.shapes.RECTANGLE, { ..., fill:{ color:"0088CC", transparency: 50 } });
// 圆角矩形：rectRadius 只在 ROUNDED_RECTANGLE 上有效，RECTANGLE 无效
slide.addShape(pres.shapes.ROUNDED_RECTANGLE, { ..., rectRadius: 0.1 });
// 阴影：让卡片突出用这个，不要用边缘条纹
slide.addShape(pres.shapes.RECTANGLE, {
  ..., fill:{color:"FFFFFF"},
  shadow: { type:"outer", color:"000000", blur:6, offset:2, angle:45, opacity:0.15 }
});
```

**阴影参数表**：

| 属性 | 范围 / 说明 |
|---|---|
| `type` | `"outer"` / `"inner"` |
| `color` | 6 位十六进制（**不带 `#`，不能 8 位**） |
| `blur` | 0–100 pt |
| `offset` | 0–200 pt，**必须非负**（负数会损坏文件） |
| `angle` | 0–359°，从 3 点钟方向顺时针（45=右下，135=左下，270=向上） |
| `opacity` | 0.0–1.0（透明度用这个，**绝不要编进 color**） |

> 要向上投影（比如靠近底部的卡片）：用 **`angle: 270` + 正 offset**，**不是**负 offset。
> **渐变填充不被原生支持**——用渐变图片当背景代替。

### 4.5 图片

三种来源：本地 `path` / URL `path` / **base64 `data`（更快）**。

**三种定尺模式**（这是"绝不拉伸"原则的落地）：

```javascript
{ sizing: { type: 'contain', w:4, h:3 } }                    // 装进去，保持比例
{ sizing: { type: 'cover',   w:4, h:3 } }                    // 填满，保持比例（可能裁剪）
{ sizing: { type: 'crop', x:0.5, y:0.5, w:2, h:2 } }         // 裁特定区域

// 按原始宽高比计算尺寸并居中
const origW = 1978, origH = 923, maxH = 3.0;
const calcW = maxH * (origW / origH);
const centerX = (W - calcW) / 2;
slide.addImage({ path:"image.png", x: centerX, y:1.2, w: calcW, h: maxH });
```

支持 PNG / JPG / GIF / SVG（SVG 在现代 PowerPoint / Microsoft 365 可用）。

### 4.6 图表

**核心原则：图表保持原生、可编辑。** 按"PowerPoint 能表达什么"来选方案，而不是"什么最好写"：

| 情况 | 做法 |
|---|---|
| 库原生支持（柱/条/线/饼/面/散点/气泡/雷达/环图/组合） | 用 `addChart()`，**绝不**渲染成图片 |
| PPT 原生但库没暴露（趋势线、误差线） | 保持原生：**自己算额外系列**（如回归线作为第二个 LINE/SCATTER 系列）或注入 OOXML。**不要**退回 matplotlib PNG——会失去可编辑性 |
| 确实无原生表达（桑基图、网络图、弦图、复杂统计图） | **只有这时**才渲染成图片用 `addImage()` 插入 |

**让图表不显旧**：

```javascript
slide.addChart(pres.charts.BAR, chartData, {
  x:0.5, y:1, w:9, h:4, barDir: "col",
  chartColors: ["0D9488","14B8A6","5EEAD4"],               // 匹配调色板
  chartArea: { fill:{color:"FFFFFF"}, roundedCorners: true },
  catAxisLabelColor: "64748B", valAxisLabelColor: "64748B", // 弱化轴标签
  valGridLine: { color:"E2E8F0", size:0.5 },                // 只保留值轴细网格
  catGridLine: { style: "none" },
  showValue: true, dataLabelPosition: "outEnd", dataLabelColor: "1E293B",
  showLegend: false,                                        // 单系列隐藏图例
});
```

**⚠️ 堆积柱状图不能用 `outEnd` 标签**（OOXML 硬限制）：

`c:dLblPos` 受分组方式限制——**stacked / percentStacked 只允许 `ctr` / `inBase` / `inEnd`**；`outEnd` 只在 `clustered` 下合法（折线：ctr/l/r/t/b；饼/环：bestFit/ctr/inEnd/outEnd）。

pptxgenjs 不会拦你写 `barGrouping:"stacked"` + `dataLabelPosition:"outEnd"`，**LibreOffice 也渲染正常**——**只有 PowerPoint 会拒绝、触发"修复"、把图表丢掉**。这是最危险的一类 bug：本地验证全过，到用户机器上炸。

**要高亮单根柱子，用逐点配色**（`varyColors: true` + `chartColors` 数组）而不是改标签位置。

### 4.7 母版、表格、背景、备注

```javascript
slide.background = { color: "F1F1F1" };                     // 纯色
slide.background = { color: "FF3399", transparency: 50 };   // 带透明
slide.background = { path: "https://.../bg.jpg" };          // 图片 URL
slide.background = { data: "image/png;base64,..." };        // 图片 base64

// 表格支持合并单元格（colspan）
slide.addTable([...], { x:1, y:1, w:8, h:2, border:{pt:1,color:"999999"}, fill:{color:"F1F1F1"} });

// 母版
pres.defineSlideMaster({
  title: 'TITLE_SLIDE', background: { color: '283A5E' },
  objects: [{ placeholder: { options: { name:'title', type:'title', x:1,y:2,w:8,h:2 } } }]
});
// 演讲者备注（只在演示者视图可见）
slide.addNotes("Open with the FY25 revenue headline; pause after the number. ...");
```

**演讲者备注的示范写法**值得注意——不是"这页讲什么"，而是**给讲者的提示**："用 FY25 营收头条开场；数字后停顿。如果被问到 Q3 下滑：供应链问题，Q4 已解决。"

### 4.8 常见坑清单（文件损坏 / 视觉 bug / AI 味）

1. **十六进制色绝不带 `#`** —— `"FF0000"` ✅ / `"#FF0000"` ❌（会损坏文件）
2. **绝不把不透明度编进 hex** —— 8 位 hex（如 `"00000020"`）损坏文件；用 `opacity` 属性
3. **用 `bullet: true`** —— 绝不用 unicode `•`（双圆点）
4. **数组项之间用 `breakLine: true`**
5. **避免 bullet 配 `lineSpacing`**（间隙过大）——改用 `paraSpaceAfter`
6. **每份演示文稿新建实例** —— 不要复用 `pptxgen()` 对象
7. **不要在多次调用间复用 options 对象** —— pptxgenjs 会**原地修改对象**（例如把 shadow 值转成 EMU），共享会导致第二个形状损坏。**用工厂函数返回新对象**：
   ```javascript
   const makeShadow = () => ({ type:"outer", blur:6, offset:2, color:"000000", opacity:0.15 });
   slide.addShape(pres.shapes.RECTANGLE, { shadow: makeShadow(), ... }); // ✅
   ```
8. **不要给卡片加边缘强调条** —— 用 `fill` 浅色调或 `shadow` 区分
9. **富文本数组每个 run 一个 `<a:pPr>`** —— 同段多 run 会产生重复且 schema 非法的段落属性，**只有 PowerPoint 会崩**（详见 §4.2）

## 5. 模板继承与编辑：两条工程流程

### 5.1 基于用户模板创建（Template Inheritance）

开头就是一整块**强制性条款**：

> **模板继承（强制）**——如果用户提供了现成 PPT、公司模板或参考文件，**必须**走"模板继承"流程，而不是从头做一个像样的仿制品：
> - 分析字体、配色、间距、页脚、页码、占位符、品牌元素
> - 建立"源页 → 新页"的映射
> - **尽可能继承现有 layout**，而不是重建一套
> - 只修改允许修改的元素
> - 除非用户要求重做，否则保留原模板的视觉语言
> - 如果原模板没有任何页面能承载目标内容，**明确说明这一限制**并提出最接近的替代方案

**两种模式（"当模板用"其实是两件不同的事）**：

| 模式 | 用户信号 | 做法 |
|---|---|---|
| **Clone & fill** | 新大纲或自由结构——"做成这个风格" / "用这个模板做一份 X" | 克隆模板页并填充；**按角色**挑选要复用的页，让大纲迁就模板能提供的页型 |
| **Fill-in** | 新内容与模板页约 1:1 对应（换数据 / 换客户） | 原位替换——即下面的 Approach A |

两者都原生编辑 .pptx 并输出可编辑 PowerPoint；**绝不**把模板任务丢进"从零 HTML 管线"。

**研究模板（生成任何内容之前）——程序化优先，视觉只为打破平局**：

- 用 python-pptx **清点每个文字形状**（**递归进 GROUP**）：位置、尺寸、字体、当前文本长度。**原文长度就是预算上限**
- **给每页分类角色**（封面/章节/内容/数据/引语/结尾……），这张角色图就是规划用的版式目录。**角色要从清点数据推导，不要靠看图**：
  - 封面 = 少量形状 + 超大标题（≥36pt）和/或满版背景图
  - 章节页 = 只有 1–2 个短文本框
  - 数据页 = 有 60pt+ 的数字形状
  - 引语页 = 单个大号居中长文本框
  - 内容页 = 若干正文框
- 回答那个决定性的结构问题：**设计是活在 `slideLayouts` 里（有真占位符），还是画在 slides 上的自由文本框、而 layout 是空的？**（下载来的模板常见后者 → Clone & fill 必须在 XML 层克隆）
- 读设计的源头：`presentation.xml` 取页面尺寸（**绝不假设 16:9**）；`theme1.xml` 取颜色和字体——**slide XML 用的是 `schemeClr` 间接引用，真正的 hex 在 theme 里**（被母版的 `clrMap` 重映射），中文文本走 `<a:ea>` 字体

**计划，然后构建——永远在用户文件的副本上**：

- 先写一个短计划：最终页序；每页的模板来源（克隆哪个 slide index，或哪个 layout name）**按角色选**；替换文本**在预算内**写。如果用户大纲与模板结构冲突，**摆出取舍**而不是硬来
- Fill-in：按下节 Approach A 执行
- Clone & fill：先实体化页面——layout 是真的时候用 `add_slide` + 填占位符；否则**在 XML 层克隆**（复制 slide part + 它的 `.rels`，重新登记 media rId，加进 `sldIdLst` 和 `[Content_Types].xml`）。**本 skill 不带任何辅助脚本——克隆自己写**，可以进程内做（`copy.deepcopy(src.slides[i]._element)` + `prs.part.relate_to(...)` 重建每个 rel），或用 `zipfile` 解包（`extractall` → 改 XML → 重打包：**`[Content_Types].xml` 必须作为第一个条目写入，用 `ZIP_DEFLATED`，不要添加目录条目**）。然后逐页替换内容（**映射要按 slide 作用域**——克隆页共享相同源文本）、换图（替换 image part 字节，**保留形状和 rId**）、**最后删除不用的模板页，从高索引开始**

**验证（报告完成前强制）——纯程序化检查，不渲染**：

- **页序与页数**：`sldIdLst` 计数对照计划
- **残留占位符**：grep slide XML 找 `Click to add`、`xxx`、`lorem`、`TODO`、`[insert`
- **图片断链**：确认克隆页上每个 image rId 都解析到真实 media part（**空框来自悬空 rel**）：遍历 `slide.part.rels`，断言每个非外部 rel 都有 `target_part` 且 `.blob` 非空
- **文件还能打开**：用 `Presentation(path)` 重新打开并遍历所有形状。悬空 rel 或畸形 slide XML 会在这里抛异常——**这个"加载并遍历"就是 XML 合法性检查**（skill 里没有 `validate.py`）
- **字体与颜色未变**：diff run/theme 的字体+颜色，而不是靠眼睛看
- **溢出 / 碰撞**：对最终文本复查预算规则（`len ≤ orig_len × 1.1`），并比较每个形状的 `left+width` 与邻居。**通过预算就是这里的溢出防线**，任何超预算的形状都当作真实缺陷修掉

### 5.2 编辑现有 PPT

- **Approach A —— `python-pptx` 脚本**：文本替换、删/重排页面、任何需要保留字体/颜色/版式的编辑。**更简单更安全**
- **Approach B —— 原始 OOXML**：动画、切换、批注、备注 XML、主题微调、自定义 layout 编辑——**python-pptx 够不到的一切**

#### Approach A 工作流

1. **清点 deck**——遍历每页，**递归进 GROUP**（`shape_type == 6`），`print(repr(para.text))`。**以清点结果为替换键的唯一真相来源**；渲染出来的文本常含隐藏字符，复制粘贴活不下来
2. **Helper 函数**（保持构建脚本短小）：`iter_text_frames`（递归 GROUP 生成 `(shape, text_frame)`）、`_norm`（**匹配前先剥掉软换行 `\x0b`**）、`replace_in_paragraph`（**只改第一个 run 以保留格式**，删掉其余 run）、`apply_replacements`（先整框匹配，再逐段匹配）、`delete_slide`

#### 「先给每个形状算预算」（最重要的一节）

> 大多数溢出 bug 来自**不知道目标框容量就开始生成文案**。起草任何替换文本之前，先遍历一遍 deck，产出一份**容量清单**，然后把它作为硬约束喂给内容生成步骤。

对每个含文字的形状收集：`slide_idx, shape_id, w_cm, h_cm, font_pt, orig_text, orig_len`。然后：

- **`budget = orig_len × 1.1`**。模板设计者已经为这个框调好了 `orig_len`——**把它当上限，不是起点**。**这一条规则就是真正的溢出防线**；不要再用"宽/行高估算"过度工程化它（字形宽度随字体和 CJK/拉丁混排而变，任何 `chars_per_line` 公式都只是粗略猜测，而 `orig_len` 上限已经涵盖了它）
- **角色判定**：`h_cm < 1.5` **或** `orig_len ≤ 8` **或** `font_pt ≥ 20` → `"label"`；否则 `"body"`

生成步骤必须遵守的规则：

- **标签框**：只用短词组。不写完整句、不带结尾标点、不做"术语+解释"式展开。**硬上限 = `max(orig_len, 8)`**。SWOT 格子、时间线标签、KPI 标签都属于这类
- **正文框**：不超 `budget`。**字号从模板继承**；缩字号是最后手段，不是首选
- 内容确实更长且版式允许时，**把框本身加宽**（`widen_to_fit`）而不是缩字号——但要先确认 `left + width` 不会撞到下一个形状

#### 替换后过长的处理（按成本从低到高）

1. **优先按预算裁剪**。从清单里取 `shape.width` × `font_size`，把替换文本裁到适配原始视觉预算。**数字徽章 / 小标签框（`width ≤ 0.7"`、`font_size ≥ 16pt`）最多放约 3–4 个字符**
2. **加宽形状**（内容确实更长且旁边有空位时）。**先检查不会与邻居碰撞**
3. **缩小字号**（只在表格单元格、数字徽章这类"加宽会破坏网格"的紧凑框上用）。**最后手段——它会明显破坏排版节奏**

> ⚠️ 两个 helper **只往 XML 里写 autofit 标志**——python-pptx **自己不计算**重排后的形状或缩放后的字号。**真正的适配是打开文件时由查看器（PowerPoint / LibreOffice）应用的**，所以**你的程序化溢出检查看不到结果**。**优先用"按预算裁剪"，那个不需要渲染就可验证。**

**绝不要用 `word_wrap = False`**：它会让文字在 PowerPoint 里**隐形溢出**框外，导出时看着就是坏的。

#### 关键陷阱

- **软换行 `\x0b`** 会静默破坏精确匹配——**键和查找值都要 `_norm()`**
- **GROUP 形状**（`shape_type == 6`）藏着文本框——**必须递归**
- **改第一个 run** 保留格式；`paragraph.text = ...` 会**摧毁**格式
- **短 token 会撞车**。`"01"`、`"%"`、`"18"` 在多页反复出现——保留恒等映射，或**按 slide index 作用域**，**绝不能做全局跨页映射**如 `"18": "12"`
- **删页要从高索引开始**——先删 index 5 会让之后每个索引都前移一位

### 5.3 代码风格

- 写简洁代码
- 避免啰嗦的变量名和冗余操作

## 6. 方法论提炼：这份 skill 的六个核心思想

1. **设计规范与工程实现分离**
   Part 1 是纯设计语言（配色/版式/字体/间距），Part 2 才是 API。设计规范能被复用到任何渲染器上，这是结构上最值得学的一点。

2. **反 AI 味被系统化成一张可执行清单**
   不用"要好看"这种空话，而是列出**具体禁止项**：标题下划线、边缘色条、通栏色带、卡片网格重复、默认蓝色、奶油背景、正文居中……每一条都指向一个可判定的特征。

3. **"约束"代替"估算"**
   溢出防护不靠计算字符宽度，而靠 **`budget = orig_len × 1.1`**——**信任模板设计者已经调好的长度**。这是一个非常工程化的取舍：用不可靠的精确计算，不如用可靠的经验上界。

4. **可编辑性优先于渲染效果**
   图表能用原生就用原生，用不了就自己造系列或注入 OOXML，**只有真正无法原生表达的图**（桑基、网络图）才转图片。因为用户拿到 PPT 是要改的。

5. **本地可验证优先于外部服务**
   视觉 QA **只做一次**、用本地 `pdftoppm` + judge 子代理，**明令禁止调外部 VLM**。模板验证全部做成**不需要渲染就能判定**的程序化检查（页数、占位符、rel 链、能否打开、预算）。这是对"渲染验证不可靠"的直接回应。

6. **踩坑经验被写成第一手警告**
   `<a:pPr>` 重复、堆积图 `outEnd` 被 PowerPoint 拒绝而 LibreOffice 放过、`#` hex 损坏文件、pptxgenjs 原地突变 options、软换行 `\x0b` 破坏匹配……这些都是"LibreOffice 能过、PowerPoint 会炸"的**验证盲区**。skill 反复强调 **"预览过了不代表没问题"**，并给出各自的安全替代方案。

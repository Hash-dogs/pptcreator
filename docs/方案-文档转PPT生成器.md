## 二、⚠️ 阻塞项：「XML 合并」有两种完全不同的意思

你在第 9 条选了"程序做 XML 合并"，但这句话有两种解释，**结果差别极大，必须先定下来**：

### 含义 A：页面级合并 —— 把自由生成的**整页**搬进公司模板文件

- ✅ 保留自由页面的设计，第一版什么样，终稿就什么样
- ❌ 那些页在公司模板文件里是**外来页**：它们引用的是生成时的母版/主题，不是公司的
- ❌ 背景不一致 —— 直接违背你"内容只需保证背景一致"的要求
- ❌ 这正是 zcode 原文警告的情况：*"a foreign page next to the template's real pages is instantly visible and loses the theme"*

### 含义 B：内容级合并 —— 只把自由页的**内容**搬到公司模板的页上，版式用公司的

- ✅ 背景/母版/主题全是真的，公司模板约束满足
- ❌ 自由页面的**设计全部丢弃** —— 那"第一版仅预览"里的设计就没有意义了
- ❌ 预览和终稿长得完全不同，预览会误导人

**两者都不完全满足你的目标。** A 满足了"第一版即终稿"但破坏公司模板；B 满足了公司模板但第一版白做。

### 唯一能同时满足两条的路

把 5–6 套版式**直接画在公司模板的 `Full Blank` / `Title Only` 上**。

这时"合并"退化成一件小事：**插入封面/目录/章节页/封底 + 重接页码**——工作量比 A/B 小一个数量级，且没有外来页问题。

## 三、两个你已确认、但后果要说清的取舍

### 取舍 1：「程序做 XML 合并」= 整个项目最难的一步

这是 zcode 那份 SKILL.md 里**唯一明说"没有现成代码、要你自己写"**的一步：

> *No helper scripts ship with this skill — write the clone yourself*

要处理：slide part + `.rels` + 媒体文件 rId 重登记 + `[Content_Types].xml`（必须作为第一个条目写入）+ `ZIP_DEFLATED` + 母版/主题引用 + 页码页脚重接。zcode 给的校验清单里专门有一条"图片断链"（空框就是这么来的）。

**建议**：无论最终选 A 还是 B，先写一个**最小验证**——生成 2 页、合并进模板、用 officecli 的 `broken_part_ref` 检查 + 人工打开确认。跑通了再铺开。

### 取舍 2：「只把有问题的页给 AI 看」= 看不见"生硬"

程序检查（包围盒）能查出**硬伤**：出界、重叠、字号过小。但**查不出"生硬"**——而这恰恰是你最初要解决的问题。

我做过实验：造一份含 5 个故意缺陷的 pptx，`officecli view issues` **只查出"出界"**，漏掉溢出、重叠、字号过小、低对比。

所以"只把有问题的页给 AI 看"的隐含逻辑是"程序没报错的页 = 好页"，而**程序没报错的页里恰恰藏着你要解决的问题**。

**低成本补救**：officecli 支持 `view screenshot --grid` 一次渲染整份 deck 的**缩略图联系表**。一次调用让 AI 整份扫一遍，成本很低，能抓到"生硬"。**建议至少加这一个粗看环节。**

## 四、架构草案

```
输入（pdf / docx / pptx / 图片）
   ↓
① 解析        提取文字、表格、图片，保留来源页码
   ↓
② 大纲        AI 生成大纲  →  【人工确认 / 修改】← 你要求的"中途改"
   ↓
③ 内容规划    AI 提炼内容 + 分配页面 + 指定每页用哪套版式（从 5–6 套里选）
              ★ 同时输出"关键信息清单"（数字/百分比/专有名词/结论句）
   ↓
④ 渲染        按版式生成              → 预览版 PPTX
   ↓
⑤ 程序检查    溢出 / 重叠 / 出界 / 字号下限 / 关键信息比对
   ↓ 有问题                                  ↓ 没问题
  AI 看图 → 修 → 回到 ⑤                  （可选：整份缩略图粗看）
   ↓
⑥ 套模板      XML 合并 → 终稿 PPTX
   ↓
⑦ 输出        网页下载
```

**关键技术选型（待定，见阻塞项）**

|---|---|---|
| 渲染库 | python-pptx / pptxgenjs | **pptxgenjs 打不开既有 .pptx**（已查证 4.0.1 只有 addSlide/defineSlideMaster/writeFile/write/stream/tableToSlides）。要"真的用上公司模板"就必须用 python-pptx |

## 五、5–6 套版式的候选（从 zcode 规范推导）

> 📌 **本节是历史记录，不是现状。** 这里的「5–6 套」是最初的保守目标，
> 实现走到了 **20 套**（12 套是本节推导出的形态，8 套来自实测缺口与开源方案调研）。
> 现状以 [`README.md` 的「版式系统」](../README.md) 与 `src/pptgen/layout_spec.py` 为准 ——
> 那里是版式的单一真相来源，20 套各自的用途、容量、适用意图都在里面。

zcode Part 1 明确偏向的展示形态：**图表/图示优先于文字、无容器分组、单一视觉焦点、大数字标注、对比列、流程链**。

据此候选：

| # | 版式 | 适用内容 | zcode 依据 |
|---|---|---|---|
| 1 | 大数字 + 说明 | 核心指标 | "Large stat callouts (60–72pt)" |
| 2 | 双栏/多栏对比 | before/after、优劣、方案对比 | "Comparison columns" |
| 3 | 流程链 / 时间线 | 步骤、阶段、进展 | "numbered process chains" |
| 4 | 图表页 | 任何量化内容 | "图表原生构建" |
| 5 | 行列表 / 发丝分隔 | 要点罗列（**替代卡片**） | "row list + hairline separators" |
| 6 | 单句强调 / 引语 | 关键结论、章节过渡 | "single-statement emphasis" |

**避坑（zcode 明令禁止，直接写成检查规则）**：标题下装饰性下划线、边缘色条/通栏色带、卡片网格连续出现、正文居中、默认蓝色、奶油/米色背景、全篇一个字号。

> 注意：zcode 的配色规则（Background→Primary→Accent）**与公司模板冲突**——模板已有自己的色系。所以**配色不采用 zcode 的，只采用它的版式与避坑规则**。

**验证内容**：用 python-pptx 打开 `迈胜PPT模板.pptx`，在真实 layout 上画 2 页（页 A = 大数字版式 + 嵌入图片；页 B = 标题 + 原生图表），保留公司封面/目录/封底，渲染后逐项检查。

### ✅ 走通的部分

| 项 | 结果 |
|---|---|
| python-pptx 打开公司模板、用真实 layout 加页 | ✅ |
| 母版/主题/背景继承 | ✅ 页 B 保住了红顶栏 + MEVION 徽标 + 装饰弧线 |
| 图片嵌入 | ✅ 无空框，`blob` 可解析（3935 / 1044353 / 13941 字节） |

| officecli `view issues` | ✅ 0 issues（含 `--type structure`） |

### ❌ 发现的三个问题

#### 问题 1（严重，已修复）：先删页再加页 → partname 撞名 → **封底丢失**

python-pptx 的 `add_slide` 按"现有 slide 部件数量"计算新文件名。**先删内容页（部件数 4→3）再新增**，新页被命名为 `slide4.xml`，与既有封底撞名：

```
rId4 -> slides/slide4.xml   ← 模板封底
rId5 -> slides/slide4.xml   ← 新页 A，同名！
```

结果：zip 内 `slide4.xml` 出现两次，两个 rId 指向同一部件，实际输出变成 `封面 → 目录 → 页A → 页B → 页A`，**模板封底被覆盖丢失**。

> **规则：所有 `add_slide` 必须在删页之前完成。**
> **必配校验**：保存后检查 ① zip 内无重名条目 ② `sldIdLst` 的目标互不重复。

#### 问题 2（重要）：`Full Blank` 不能用

实测渲染：`Full Blank` 出来的页是**纯白**——没有红顶栏、没有 MEVION 徽标、没有弧线。

根因：`Full Blank` 上有个 `Rectangle 3`（`x=9.19, y=0, 4.15×1.24`，纯色填充）**正好盖住母版的 MEVION 徽标**；同时它既没有红顶栏（各 layout 上的 `Rectangle` @ `0,0,10.70×0.10`）也没有弧线（`Picture` @ `10.19,4.34`）。

**各 layout 自带的品牌元素实测：**

| layout | 红色顶栏 | MEVION 徽标 | 装饰弧线 | 内容占位符 | 结论 |
|---|---|---|---|---|---|
| Title and Content | ✅ | ✅ | ✅ | ✅ 12.00×5.00 | 版式受限 |
| Two Content | ✅ | ✅ | ✅ | ✅ 两个 6.00×5.00 | 版式受限 |
| **Title Only** | ✅ | ✅ | ✅ | ❌ 只有标题位 | **✅ 推荐：有品牌 + 自由** |
| **Blank** | ✅ | ✅ | ✅ | ❌ 全空 | **✅ 推荐：有品牌 + 自由** |
| **Full Blank** | ❌ | ❌ | ❌ | ❌ | **❌ 不可用：无任何品牌元素** |
| Agenda | ✅ 左侧红弧 | ✅ | ❌ | ✅ | 目录页专用 |
| Primary Title Slide / Subtitle 1,2 | ❌ | ✅ | 各自不同 | — | 骨架页专用 |

#### 问题 3：自由构图 ≠ 好看

我画的"大数字页"实测观感不佳：`87` 与 `亿美元` 基线不齐；右下大片留白；三条要点挤在底部左半边。

**这恰好复现了你最初要解决的"生硬"问题**——说明"让 AI 自由画"本身不解决观感，版式本身的设计质量仍是关键。**这条支持"先做乙（固定版式）"的选择。**
